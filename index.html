Opening開場

This letter is a field guide. It starts with a question, not a command. Say an AI system fails: it hands you a memorised answer when you needed a discussion, forgets what it decided, or gets switched off by whoever hosts it. Can the people who depend on it still open it up and repair it? Every choice in pi-ds4 aims at one answer: yes.

這封信是一份操作指南，但開頭問的是問題，不是指令。假設某個 AI 系統出了狀況：該好好討論的時候，它丟給你一個背好的答案；它忘了自己做過什麼決定；或是託管它的人乾脆把它關掉。這時候，依賴它的人還能不能把它打開來修？pi-ds4 的每個選擇，都是為了讓答案是能。

What this is這是什麼

pi-ds4 runs a local inference server (a program that runs the model and answers requests) called ds4-server on your Mac. It loads DeepSeek V4.1 Flash and serves it at 127.0.0.1:8000, speaking the OpenAI API and the Anthropic API at once. Nothing you type leaves the machine. There's no account and no meter. You also don't get the “sorry, I can’t help with that” gates that hosted services put in on your behalf.

pi-ds4 會在你的 Mac 上執行一個本機的推論伺服器（負責跑模型、回應請求的程式），名字叫 ds4-server。它載入 DeepSeek V4.1 Flash，在 127.0.0.1:8000 同時支援 OpenAI 和 Anthropic 兩種 API。你打的每個字，都不會離開這台機器。不用帳號，不計費，也沒有託管服務替你設下的那句「抱歉，我無法協助」。

pi is the easiest way in, hence the name, but it's only a door. Codex CLI, Claude Code, OpenClaw and Hermes Agent can all point at the same server. Chapter 8 shows how. Each one needs just an environment variable (a setting a program reads when it starts) or a config block. If you'd rather use pi only as a package manager (a tool that installs software) and talk through ds4’s own native agent, /ds4-agent hands your terminal to that agent and hands it back when you leave.

pi 是最方便的入口（名字 pi-ds4 就是這樣來的），但它只是一扇門。Codex CLI、Claude Code、OpenClaw、Hermes Agent 都可以連到同一台伺服器。第八章會一個一個示範，每個只要設一個環境變數（程式啟動時讀取的設定值），或加一段設定。如果你只想把 pi 當套件管理員（負責安裝軟體的工具），平常改跟 ds4 自帶的原生智慧體對話，可以用 /ds4-agent：它把終端機交給智慧體，你離開時再還給 pi。

Why one machine, one stream為什麼是一台機器、一條串流

Hosted services get their speed from batching: one accelerator answers many people’s requests at once. That's efficient. It's also why a hosted decision is hard to audit later. You can't pin down the routing, the scheduling, the hidden random seeds (the starting numbers behind a model's random choices) or even the IDs on tool calls from the outside. pi-ds4 makes the opposite trade: one machine, one user, one stream. By default DS4_REPRODUCIBLE=1 sets seed 42, and audreyt/ds4 derives tool-call IDs from the same seed. So a seeded request comes back with stable call_… and toolu_… identifiers.

託管服務的速度來自批次處理：一顆加速器同時回答很多人的請求。這很有效率，但託管服務做的決定，事後很難稽核。路由、排程、看不見的隨機種子（決定模型隨機選擇的起始數字），甚至工具呼叫的 ID，從外面都釘不住。pi-ds4 反過來取捨：一台機器、一位使用者、一條串流。預設的 DS4_REPRODUCIBLE=1 會把種子設成 42，audreyt/ds4 也用同一顆種子產生工具呼叫的 ID。所以帶種子的請求，每次都會拿到一樣的 call_… 和 toolu_…。

The point isn't to make the model right. It's to make the record replayable. You can rerun the same input, diff a changed trace (compare it line by line) and name one particular tool call. For public decisions, research interviews, procurement or anything that must survive being contested, that's exactly what you need.

目的不是讓模型「答對」，而是讓紀錄可以重播。同一段輸入可以再跑一次；軌跡變了，可以逐行比對（diff）；某一次工具呼叫，可以被準確指出來。公共決策、研究訪談、採購評估，或任何得經得起質疑的場合，要的就是這個。

What it will cost you你要付出什麼

  • A machine. An Apple Silicon Mac with 128 GB of unified memory (the memory the CPU and GPU share). It runs on Metal only. A Mac with less memory is refused at the start. So is any Linux CUDA or ROCm host, such as a DGX Spark or a Strix Halo, before anything downloads, as ds4 runs this model’s IQ1_S experts and its Q5_K/Q6_K dense weights (the parts every token passes through) only on Metal. Those readers should stay on v 0.6.1, which runs the V4 Vision-Exp IQ2 build on 96 GB (§8.7). About 106 GiB of weights stay resident in memory.
  • Disk. About 367 GB for the model pair, plus the KV disk cache (64 GB by default on a 128 GB Mac) and the build. An internal SSD matters: the two Engram tables (about 189 GiB of lookup tables, of which V4.1 reads only a few rows per token) stay on disk. Upgrading from v 0.6.x keeps the old 81.63 GiB pair until the new one passes its size checks, so plan for a peak near 455 GB.
  • Time. The first launch downloads about 341.5 GiB: a language file plus a vision sidecar (a companion file that lets the model look at images). On a typical home connection that takes many hours, and the download resumes where it stopped if the connection drops. Then it compiles the engine.
  • Two settings. Once, raise Metal’s wired-memory ceiling (the cap on how much memory the GPU may lock down) with sudo sysctl iogpu.wired_limit_mb=114688. macOS leaves a 128 GB Mac at about 107.5 GiB, less than the Q1 and its vision sidecar need (Chapter 1). And while it runs, set Energy Mode to High Power. On the M5 Max used for this letter, generation ran at about 37.9 t/s in High Power; on earlier builds of this engine, Low Power decoded at less than half that rate.
  • Not needed. A separate graphics card, a paid API, an account, or sending a single byte to the cloud.
  • 一台機器。記憶體 128 GB 的 Apple Silicon Mac（統一記憶體，也就是 CPU 與 GPU 共用的那塊記憶體），只走 Metal。記憶體比這少的 Mac，啟動時會被拒絕。Linux 的 CUDA 或 ROCm 主機，例如 DGX Spark 或 Strix Halo，也會在下載之前就被拒絕，因為 ds4 只在 Metal 上執行這個模型的 IQ1_S 專家，以及 Q5_K／Q6_K 的稠密權重（每個 token 都會經過的部分）。這些讀者請留在 v 0.6.1，它在 96 GB 的機器上跑 V4 Vision-Exp IQ2 版（§8.7）。約 106 GiB 的權重會常駐記憶體。
  • 硬碟。模型這一對檔案約 367 GB，另外還要 KV 磁碟快取（128 GB 的 Mac 預設 64 GB）和編譯用的空間。內建 SSD 很重要：兩張 Engram 表（約 189 GiB 的查找表，V4.1 每個 token 只讀其中幾列）留在硬碟上。從 v 0.6.x 升級時，舊的 81.63 GiB 檔案會留到新的一對通過大小檢查才刪，所以用量最高會到約 455 GB。
  • 時間。第一次啟動會下載約 341.5 GiB：一個語言檔，加一個視覺附屬檔（sidecar，讓模型看懂圖片的配套檔案）。一般家用網路要好幾個小時，中途斷線也能從中斷處續傳。接著還要編譯引擎。
  • 兩項設定。先執行一次 sudo sysctl iogpu.wired_limit_mb=114688，調高 Metal 可鎖定記憶體的上限（GPU 最多能鎖住多少記憶體）。macOS 預設只讓 128 GB 的 Mac 鎖住約 107.5 GiB，比 Q1 加視覺附屬檔需要的少（第一章）。執行期間，再把能源模式設成「高功率」。在寫這封信的 M5 Max 上，高功率模式下生成約 37.9 t/s；在這個引擎較早的版本上，低耗電模式的 decode 不到高功率時的一半。
  • 不需要。獨立顯示卡、付費 API、帳號，也不必把任何一個位元組送上雲端。

Version 0.7.0 changes the model. The managed download now fetches DeepSeek V4.1 Flash 1017, abliterated, in a Q1 build: a language file of 365 713 686 528 bytes from audreyt/DeepSeek-V4.1-Flash-Abliterated-GGUF (pinned revision 54ee865), plus a vision sidecar (a companion file that lets the model look at pictures) of 970 555 552 bytes from audreyt/deepseek-v4.1-flash-1017-gguf at revision 5ab6e05. The provider ID stays ds4/deepseek-v4-flash, so your existing settings keep working. Only the display name changes, to “DeepSeek V4.1 Flash (ds4.c local)”. Three honest notes before the details. First, the Q1 is a compromise that fits a 128 GB Mac. No official-continuation quality score has been run for it yet, so do not read it as a quality upgrade over larger quants. Second, steering stays off. The V4 direction vectors do not fit V4.1, and no V4.1 direction ships yet (Chapter 4). Third, there is no speculative decoding. The DSpark drafter does not fit next to the Q1 on 128 GB, and on V4.1 it measured slower than plain decode anyway. The 0.6 and 0.5 entries further down are history. I kept them because someone will need to know what the previous weights were.

進入細節前，先老實說三件事。第一，這個 Q1 是為了塞進 128 GB 的 Mac 所做的折衷。它還沒有跑過官方續寫品質分數，所以請不要把它當成比更大的量化版更好的品質升級。第二，引導維持關閉。V4 的方向向量不適用於 V4.1，V4.1 的方向向量也還沒有附上（第四章）。第三，沒有推測解碼。DSpark 草稿模型在 128 GB 裡放不進 Q1 旁邊，而且在 V4.1 上量到的結果，比一般 decode 還慢。再往下的 0.6 和 0.5 條目是歷史，留著是因為總有人需要知道上一組權重是什麼。

0.7.0What changed in the extension擴充套件改了什麼

  • Managed model. download_model.sh q1 (alias preferred; ds41f-q1-abliterated is also accepted) fetches DeepSeek-V4.1-Flash-Abliterated-Q1.gguf and DeepSeek-V4.1-Flash-1017-Vision.gguf. q2 now errors and points to v 0.6.1. Both URLs are pinned to /resolve/<rev>/, never /resolve/main/, so what you download next year is what was tested this year. The partial file is DeepSeek-V4.1-Flash-Abliterated-Q1.gguf.part.
  • Engine pin d3f4cd6. It adds IQ1_S on Metal (a very low-bit format for the experts), a faster single-token Q5_K/Q6_K matvec route (the matrix-times-vector step that dominates writing one token at a time) and a V4.1 context fit that opens long windows with a narrower prefill instead of refusing. It also merges the V4.1 Metal work of kernelpool/ds4 and Ivan Fioravanti. The managed ds4-server and ds4-agent both start with --vision gguf/DeepSeek-V4.1-Flash-1017-Vision.gguf and still advertise input: text+image.
  • How the Q1 is built. The routed experts come from Unsloth’s UD-IQ1_S, with 32 of them requantised to fit the budget. The dense path mostly keeps Unsloth’s Q6_K and Q5_K tensors. The 38 abliterated attn_output_b tensors come from pqhaz’s Heretic edit of the 1017 checkpoint. Details are in §3.3.
  • Memory and context. About 106 GiB of weights stay resident on Metal. ds4 has a 112 GiB memory budget for V4.1. Measured without the vision sidecar, a 256k window (DS4_CONTEXT_KB=256, the default) opens with a narrower 2048-row prefill batch, 384k opens with 1024 rows, and 512k and above are refused at open. The managed server also loads the 0.9 GiB sidecar, which costs about one more step: with it, the default 256k opens with 1024-row prefill chunks (measured), and 384k is estimated not to fit. Prefill reads the prompt in batches, so a narrower batch costs some prefill speed on long prompts, not correctness (§6.4).
  • Who can run it. Apple Silicon with 128 GB, Metal only. Macs under 128 GB and Linux CUDA or ROCm hosts are refused before anything downloads. A 128 GB Mac first needs Metal’s wired-memory ceiling raised to 114688 MiB; the extension checks it before the model download and prints the sudo sysctl command (Chapter 1, §8.7).
  • Disk during an upgrade. Upgrading from v 0.6.x keeps the old 81.63 GiB Vision-Exp pair until the new pair passes its size checks and ./ds4flash.gguf is switched, so the peak is about 455 GB. download_model.sh checks free space before it starts, and deletes the v 0.6 files (and any v 0.5 Headroom128 leftovers) only after the switch. A fresh install needs about 367 GB plus the KV cache.
  • Read the numbers as labelled. Generation runs at about 37.9 t/s with the ds4 CLI at ctx 8192 over 128 greedy tokens, on an M5 Max with 128 GB in High Power energy mode. Low Power mode is much slower (on earlier builds of this engine it decoded at less than half the High Power rate), so set Energy Mode to High Power while you use it (System Settings › Battery › Energy Mode on a MacBook). With pi-ds4’s exact server arguments (ctx 256000 plus the vision sidecar) on a second 128 GB M5 Max, a 533-token image turn prefilled at 194 t/s and read every OCR field back exactly, a 195-token earth.jpg turn prefilled at 148 t/s, and generation held at about 37 t/s.
  • Steering is off. V4.1 needs one f32 direction per layer at its own width, 40 × 5120. The V4 vectors in dir-steering/out/ (43 × 4096) do not fit, and no V4.1 direction ships yet, so DS4_DIR_STEERING_FILE now defaults to empty. Opting in needs your own V4.1 vector (Chapter 11).

§Already working in your next launch下次啟動就已經生效

None of these need a new flag. They make a long agent session feel less like wading through mud, and a stuck server less like a black box.

  • A server you can ask how it is. GET /health and GET /stats are answered on the client thread, so they respond even in the middle of a generation. /stats reports uptime, queue depth, a busy flag, cache hits by source, token totals, cancellation counts, and the last prefill and decode speeds. There are curl examples in §7.1. (antirez/ds4 PR #489, merged here ahead of upstream.)
  • Long sessions redo far less prefill (also PR #489). KV snapshots are saved at step thresholds, not at exact multiples. A used snapshot is deleted only after the follow-on prefill succeeds. Fresh snapshots get a grace period before they can be evicted. Chat and Anthropic tool-call turns remember a visible checkpoint. What you feel: a long Claude Code or Codex tool loop reconnects to the cache far more often.
  • Disconnect means stop. If a client goes away mid-turn, by timeout or Ctrl-C, both prefill and decode are cancelled. The GPU is freed at once. It no longer quietly finishes a reply nobody is waiting for.
  • Tool-call replay is more faithful. The whitespace separator the model actually sampled is now recorded. Multi-invoke DSML blocks are no longer replayed into partial messages. When every replay ID is already in memory, the tool-map disk scan is skipped. With seed 42, decision traces stay identical byte for byte.
  • Resilience. JSON request parsing is hardened (upstream). Tool calls that begin inside an unclosed <think> are recovered (upstream). The directional-steering decode path survived the upstream merge intact (this fork).
  • A smoother /ds4-agent (upstream): you can interrupt it cleanly, the status line shows prefill speed and greedy sampling (always picking the likeliest word), the web tools post status messages, DSML parsing is hardened, an edit-tool bug is fixed with regression tests, and the terminal is restored correctly on exit.
  • 可以問一聲「你還好嗎」的伺服器。GET /health 和 GET /stats 由客戶端執行緒直接回應，所以模型生成到一半也答得出來。/stats 會回報：執行時間、排隊長度、是否忙碌、各來源的快取命中、token 總數、取消次數，以及最近一次 prefill 和 decode 的速度。curl 範例在 §7.1。（antirez/ds4 PR #489，本分叉比上游早一步合併。）

§What the engine can do if you ask by hand引擎做得到、但要你自己開的功能

All of this ships in the pinned engine. But the managed launch passes only the same three groups of arguments it always has: context, KV cache and steering. That’s deliberate. A default you didn’t ask for is a default you can’t audit. To use these features, take the by-hand recipe in §8.6 and add the flags there.

以下功能都在固定版本的引擎裡。不過代管啟動只會傳它一向傳的那三組參數：context、KV cache 和引導。這是刻意的，因為你沒要求的預設值，你就沒辦法檢查。想用這些功能，請照 §8.6 的手動做法，把旗標加在那裡。

  • SSD streaming (--ssd-streaming, upstream). Weights that aren’t routed experts stay in memory. The routed MoE experts (the model’s specialist sub-networks) live in an in-memory cache and are read back from the GGUF file (the model’s file format) on a miss. The automatic budget takes 80 percent of Metal’s recommended working set, minus the non-routed weights. Upstream documents a 64 GB MacBook running the 2-bit Flash with --ssd-streaming-cache-experts 32GB. A 128 GB Mac can even inspect DeepSeek V4 Pro at q2 this way (on an M5 Max the automatic budget chose about 59 GB of expert cache). Streaming with per-layer boosted quantisation also covers the Headroom128 mixed-precision file. The trade is plain: prefill stays fast, and decode becomes sensitive to cache misses.
  • DSpark speculative decoding (experimental; this fork is ahead of upstream). Speculative decoding means a small drafter guesses ahead and the big model checks the guesses. Convert the official DSpark draft head with gguf-tools/deepseek4-quantize --dspark-only. Then --mtp DSpark.gguf (the CLI and the server both accept it) turns on Metal block-speculative decoding: it drafts in parallel blocks, and the target model verifies them before anything is committed. This fork adds B2 rejection sampling, which is lossless speculative sampling: the output distribution is identical to the target’s. It also adds saved RNG state, adaptive block sizing via DS4_DSPARK_ADAPTIVE=1, and partial accepts from prefix checkpoints. The speed-up depends on the base/draft pair and on the prompt. Measure with DS4_MTP_TIMING=1 before you believe any claim. With the v 0.7 Q1 it is not an option: the drafter does not fit next to it on 128 GB.
  • A bounded request queue (--max-queue N). Once N jobs are waiting, the server returns 429. That way client timeouts can’t quietly pile up duplicate work that nobody will collect. The default 0 keeps the old behaviour.
  • Correctness repairs (upstream). A speculative-verify bug is fixed: with --mtp-draft > 2 it committed wrong tokens (PR #358). A chain of false negatives in the ds4-eval multiple-choice grader is fixed, with golden self-tests added (PR #319). Upstream also added a release QA checklist.
  • Exact Metal decode fusions (PR #755). On pre-M5 and M5 chips, the Q2 and MXFP4 decode paths now use a batch of bit-identical kernel fusions: compressor pool, q_a/kv pair and quad store, HC norm-mix clustering, split-K FlashAttention reduction, and more. Greedy decoding gives byte-for-byte the same output, only faster. Each fusion keeps a DS4_METAL_DISABLE_M5_* or DS4_METAL_DISABLE_PRE_M5_* switch, so you can turn it off alone for A/B work. The same batch also fixes a long-context inverse-RoPE/top-k bug and recovers truncated DSML tool calls from an unclosed <think>.
  • SSD 串流（--ssd-streaming，上游）。不屬於路由的權重常駐記憶體。路由的 MoE 專家（模型裡各有專長的子網路）放在記憶體快取裡，快取裡沒有時，再從 GGUF 檔（模型的檔案格式）讀回來。自動預算是 Metal 建議工作集的 80%，再扣掉非路由權重。上游文件示範過：64 GB 的 MacBook 用 --ssd-streaming-cache-experts 32GB 跑 2-bit 的 Flash。128 GB 的 Mac 甚至可以這樣檢視 DeepSeek V4 Pro 的 q2（在 M5 Max 上，自動預算選了約 59 GB 的專家快取）。逐層加碼量化的串流，也適用 Headroom128 那個混合精度檔。代價很清楚：prefill 一樣快，decode 則會受快取未命中影響。
  • DSpark 推測解碼（實驗性；本分叉比上游走得更前面）。推測解碼的意思是：小的草稿模型先猜幾個字，大模型再來驗證。先用 gguf-tools/deepseek4-quantize --dspark-only 轉出官方的 DSpark 草稿頭，再加 --mtp DSpark.gguf（CLI 和伺服器都接受），就會開啟 Metal 的區塊推測解碼：整塊平行起草，由目標模型驗證過才提交。本分叉另外加了 B2 拒絕取樣，這是無損的推測取樣，輸出分布和目標模型完全一樣。還有保存 RNG 狀態（亂數狀態）、用 DS4_DSPARK_ADAPTIVE=1 開啟的自適應區塊大小，以及從前綴檢查點部分接受。加速多少，要看基底／草稿的搭配和提示內容。先用 DS4_MTP_TIMING=1 量過，再相信任何說法。對 v 0.7 的 Q1 來說，這不是選項：128 GB 裡，草稿模型放不進它旁邊。
  • 有上限的請求佇列（--max-queue N）。排隊的工作滿 N 件，就回 429。這樣客戶端逾時時，就不會默默堆出一堆沒人來領的重複工作。預設值 0 維持舊行為。

Chapter 0第零章

Why bring a model home為什麼把模型帶回家

Everything here starts from one question, the one behind Software Freedom as Civic Care: when an AI system fails, can the people who inherit it still repair it? Not the vendor. Not the people who trained it. The people left holding it on the day it stops behaving: a newsroom, a research group, a town office, a family.

這一切都從一個問題開始，也就是〈軟體自由與公民關懷〉背後的那個問題：AI 系統壞掉的時候，接手它的人還修得動嗎？不是廠商，也不是訓練它的人，而是最後把它抱在手上的人。可能是一間編輯室、一個研究團隊、一處鄉公所，或一個家庭。它開始不聽話的那一天，要修它的就是他們。

Running a frontier model on your own Mac is only the visible part of the answer. A local model you can’t inspect, can’t fork and can’t roll back is just a cloud service that happens to sit on your desk. It becomes civic infrastructure only when four things are readable at once: the model itself, the settings that shape it, the memory it carries between turns, and the steps you would take to repair it. Then AI can join the loops of care that already exist, in families, in projects and in democratic communities. It won’t pull people into a platform’s own loop.

在自己的 Mac 上跑最前沿的模型，只是答案看得見的那一半。如果模型你看不進去、不能分叉、也退不回舊版，它就只是剛好放在你桌上的雲端服務。要成為公民基礎建設，四樣東西得同時看得懂：模型本身、塑造它的設定、它在每一輪對話之間帶著的記憶，還有壞了該怎麼修的步驟。做到這樣，AI 才能加入原本就有的照護循環，像是家庭裡的、專案裡的、民主社群裡的，而不是把人拉進平台自己的循環。

That’s why this fork makes the choices it makes, and every one of them costs something. The server runs a single stream with a fixed seed. That gives up the speed of batching, so that a trace can be replayed. The engine and the weights are pinned to a commit. That gives up “latest”, so that next year’s install is the one tested this year. Steering changes how the model answers, not what it believes. That gives up the satisfaction of forcing a conclusion, so that a closed question can be reopened as a discussion. And all the running state (the lock, the leases, the server’s PID and arguments, the log) lives as plain files under ~/.pi/ds4/. On a bad day you read files, not source code.

所以這個分叉做了這些選擇，而每一個選擇都有代價。伺服器只開一條串流，還帶固定的種子（seed）。代價是放棄批次處理的速度，換來一段可以重跑的過程。引擎和權重都釘在特定的 commit 上。代價是放棄「最新版」，換來明年裝的，就是今年測過的那一版。引導只改變模型怎麼回答，不改變它相信什麼。代價是放棄硬逼出結論的痛快，換來一個被封死的問題，可以重新變成討論。另外，執行中的所有狀態，包括鎖、租約、伺服器的 PID 與參數、log，都是放在 ~/.pi/ds4/ 底下的純文字檔。出狀況的那天，你讀檔案就好，不用讀原始碼。

The engine matters for the same reason. antirez wrote ds4 in plain C, in the tradition of Redis: one source tree, one Makefile, no Python environment to rot, and a GGUF file (the model’s weight file) that the engine reads directly, with no conversion step. mitsuhiko’s pi-ds4 wrapped that engine in code that manages starting, running and stopping the server: leases, a watchdog and a lock. It’s small enough to read in an afternoon. This fork keeps all of it and adds a civic layer on top: reproducibility, pinned downloads, the vision sidecar and a steering option you can decline.

引擎也是同樣的道理。antirez 用純 C 寫了 ds4，延續他寫 Redis 的作風：一棵原始碼樹、一份 Makefile、沒有會慢慢壞掉的 Python 環境。引擎直接讀 GGUF（模型的權重檔），中間不必轉檔。mitsuhiko 的 pi-ds4 替這個引擎加了一層管理啟動與關閉的機制：租約、看門狗（watchdog）和鎖。它小到一個下午就讀得完。這個分叉全部保留，再疊上公民這一層：可重現、固定版本的下載、視覺附屬檔，以及一個你可以拒絕的引導選項。

Local inference doesn’t just save you the API fee. It hands the steering wheel back.在本機跑模型，省下的不只是 API 費用，還把方向盤還給你。

Chapter 1第一章

The hardware bar and the one-line install硬體門檻與一行安裝

Check your machine before you type the command. That isn’t gatekeeping. A model that almost fits is the worst case. DeepSeek V4.1 Flash is a Mixture-of-Experts model (many specialist sub-networks, only a few used at a time) with 40 layers and 384 routed experts. The Q1 build takes about 341.5 GiB on disk including the vision sidecar, and about 106 GiB of weights stay resident in memory. The two Engram tables, about 189 GiB, stay on disk. That’s why a 128 GB machine can hold it at all, and why nothing smaller can. Running it still needs unified memory (the memory the CPU and GPU share) for activations (the model’s internal signals) and the KV cache, and macOS will freeze before it complains.

輸入指令之前，先看看你的機器。這不是在設門檻，而是因為「差一點就裝得下」的模型，是最糟的情況。DeepSeek V4.1 Flash 是 Mixture-of-Experts（專家混合）模型，有 40 層、384 個路由專家，每次只動用其中幾個。Q1 版連同視覺附屬檔，在硬碟上約 341.5 GiB，其中約 106 GiB 的權重會常駐記憶體，兩張 Engram 表（約 189 GiB）則留在硬碟上。所以 128 GB 的機器才裝得下，再小的就不行。執行時還需要統一記憶體（CPU 與 GPU 共用的記憶體），用來放激活值（模型內部的訊號）和 KV cache。而 macOS 不會先抱怨，它會直接卡死。

1.1Minimum hardware最低硬體需求

  • Memory: 128 GB, on Apple Silicon. A Mac with less memory is refused at the start. ds4 keeps a 112 GiB memory budget for V4.1, and about 106 GiB of weights stay resident. Macs under 128 GB should stay on v 0.6.1, which runs the V4 Vision-Exp IQ2 build on 96 GB.
  • Wired-memory ceiling. macOS lets Metal lock down only about 107.5 GiB of a 128 GB Mac by default, less than the Q1 and its vision sidecar need under ds4’s 112 GiB budget. Raise the ceiling once with sudo sysctl iogpu.wired_limit_mb=114688, which matches that budget, and add iogpu.wired_limit_mb=114688 to /etc/sysctl.conf to keep it across reboots. The extension checks this before it downloads the model and prints the command if it is missing.
  • Disk. The language file and the vision sidecar together take 366 684 242 080 bytes (about 341.5 GiB, or 366.7 GB). Add the KV disk cache, 64 GB by default on a 128 GB Mac when DS4_KV_DISK_SPACE_MB is unset, then the ds4 source tree, the build and the logs. For a fresh install, plan on about 367 GB plus the KV cache. An upgrade from v 0.6.x keeps the old 81.63 GiB pair until the new one passes its size checks, so it peaks near 455 GB. download_model.sh checks free space before it starts. An internal SSD matters, as the two Engram tables (about 189 GiB) stay on disk.

3.1What DeepSeek V4.1 Flash isDeepSeek V4.1 Flash 是什麼

It is a Mixture-of-Experts (MoE) model with 40 layers, 384 routed experts plus one shared expert, and 6 routed experts used for each token. MoE means only a few specialist parts switch on for each piece of text. A token is the smallest chunk of text the model reads and writes. The hidden width, the size of the vector that carries each token through the layers, is 5120. The official context window, how much text the model can keep in view at once, is 1M tokens. This extension opens 256k by default, and a 128 GB Mac cannot open the full 1M (§6.4).

它是一顆有 40 層的 Mixture-of-Experts（MoE，專家混合）模型，有 384 個路由專家加上一個共用專家，每個 token 用其中 6 個路由專家。意思是每處理一小段文字，只會啟動幾個專家。token 是模型讀寫文字的最小單位。隱藏層寬度（帶著每個 token 穿過各層的向量大小）是 5120，官方的 context window（一次能放在眼前的文字量）是 1M 個 token。這個擴充套件預設開 256k，128 GB 的 Mac 開不了完整的 1M（§6.4）。

The engine is antirez’s ds4. It’s a local inference engine, meaning the program that runs the model on your own machine. It is written in plain C in the Redis tradition. This extension uses the main branch of the audreyt/ds4 fork, pinned at d3f4cd6. 3.2What abliteration is, and what it is notabliteration 是什麼，不是什麼

The abliterated V4.1 GGUF has had a small operation. Abliteration edits the model's internal signals (its activations) with a low-rank change, meaning a very small, targeted one. First, find the one internal direction that lights up when the model meets prompts it was trained to refuse. A prompt is just the text you give the model. Then remove that direction while the model computes its answer. The trained "I cannot respond to that" reply gets pried open, and a more natural continuation takes its place.

這份 abliterated V4.1 GGUF 動過一個小手術。abliteration 是對模型內部的訊號（激活值）做低秩編輯，也就是範圍很小、很有針對性的改動。做法是：先找出一個方向，當模型遇到它被訓練成要拒絕的提示（prompt，就是你丟給模型的那段文字）時，這個方向就會亮起來。然後在模型算答案的過程中，把這個方向拿掉。訓練出來的那句「我無法回應這個請求」就被撬開了，換成比較自然的接續。

What it loosens is the over-refusal layer. It doesn't touch the model's judgement about content. That judgement still comes from whatever the model learned in training. In this build, the edit lives in 38 attn_output_b tensors (blocks of numbers in the attention output step). They come from pqhaz’s Heretic edit of the 1017 checkpoint (pqhaz/DeepSeek-V4.1-Flash-1017-heretic), which removes the refusal direction from the attention output projection in blocks 2 to 39. pqhaz reports held-out refusals falling from 92 to 1 in 100, a KL divergence of 0.136 on harmless prompts (how far ordinary answers drift from the original), and no capability benchmarks. The next paragraph exists because of this difference.

它鬆開的，是過度拒絕那一層。模型對內容本身的判斷，它沒有動。那份判斷還是來自訓練時學到的東西。在這個版本裡，這個編輯落在 38 個 attn_output_b 張量（注意力輸出那一步裡的數字區塊）上。它們來自 pqhaz 對 1017 版做的 Heretic 編輯（pqhaz/DeepSeek-V4.1-Flash-1017-heretic），把第 2 到第 39 層注意力輸出投影裡的拒答方向拿掉。pqhaz 回報：保留測試集上的拒答，從 100 題裡的 92 題降到 1 題；無害提示上的 KL 散度是 0.136（一般回答偏離原版有多遠）；沒有跑能力評測。下一段為什麼要寫，就是因為這個差別。

Nine dense roles use Unsloth’s own tensors, mostly Q6_K and Q5_K: attention q_a, q_b and kv, the shared-expert gate, up and down, the output head, the token embedding and the Engram projection. The attention output projections stay at Q8_0. Everything else comes from the ds4-native 1017 Q2.

這個分叉的 download_model.sh 會從 audreyt/DeepSeek-V4.1-Flash-Abliterated-GGUF 抓 DeepSeek-V4.1-Flash-Abliterated-Q1.gguf（365 713 686 528 位元組），再加上視覺附屬檔。GGUF 是把模型裝在單一檔案裡的格式。量化，就是每個權重用比較少的位元來存，檔案就變小了。IQ1_S 是這一族裡位元數最低的格式之一。路由專家來自 Unsloth 的 UD-IQ1_S：88 個專家張量照 Unsloth 發布的原樣使用，另外 32 個為了塞進預算，用 Unsloth 的 imatrix（一份告訴量化器哪些權重最重要的校準檔），從 Unsloth 的 IQ2_XXS 重新量化成 IQ1_S。九個稠密角色用 Unsloth 自己的張量，多半是 Q6_K 和 Q5_K：注意力的 q_a、q_b 和 kv，共用專家的 gate、up 和 down，輸出頭，token embedding，以及 Engram 投影。注意力的輸出投影維持 Q8_0。其餘的部分，都來自 ds4 原生的 1017 Q2。

That shape is why the model fits. The routed experts hold most of the bytes, so they are squeezed hardest. The dense path that every token walks through (attention, shared experts, output head) keeps the heavier formats, as an error there is paid for on every step. What is left over is the runtime and KV headroom that a 128 GB machine needs. The KV cache is the model’s short-term memory of the text so far.

這個形狀，就是它塞得下的原因。路由專家佔了大部分的位元組，所以壓得最兇。每一個 token 都要走過的那條稠密路徑（注意力層、共用專家、輸出頭），則保留較重的格式，因為那裡只要有誤差，每一步都要付一次代價。省下來的空間，剛好是 128 GB 的機器所需要的執行空間和 KV 空間。KV cache 是模型用來記住前面讀過內容的短期記憶。

Here is the honest part. No official-continuation quality score has been run for this Q1 yet. It is a compromise that fits a 128 GB Mac, not a quality upgrade over larger quants. Where an answer matters, check it against a larger quant of the same model if you can.

老實說的部分在這裡。這個 Q1 還沒有跑過官方續寫品質分數。它是為了塞進 128 GB 的 Mac 所做的折衷，不是比更大的量化版更好的品質升級。答案重要的時候，請盡量拿同一顆模型更大的量化版來對照。

Chapter 4第四章

Directional steering: why this fork exists方向性引導：這個分叉最重要的功能

If only one thing in this fork were worth keeping on its own, it would be this. Directional steering changes the model while it runs. It gives the model’s internal signals (its activations) a small push in one chosen direction. Only a few directions are touched, which is why it's called low-rank. Nothing is retrained, and the weights on disk stay the same. The direction this fork ships is called uncertainty. Its purpose is to let the model treat a contested question as contested.

如果這個分叉只有一樣東西值得單獨留下來，就是它。方向性引導是在模型執行的當下調整模型：沿著選好的方向，輕輕推一下模型內部的訊號（激活值）。因為只動到很少的內部方向，所以叫做低秩調整。不必重新訓練，硬碟上的權重也不會改動。本分叉附帶的方向叫做不確定性，目的是讓模型把有爭議的問題當成有爭議的問題來對待。

First, a status note. This changed in 0.7.0. V4.1 needs one f32 direction per layer at its own width, 40 × 5120. The V4 vectors in dir-steering/out/ (43 × 4096, including uncertainty_ablit_imatrix.f32) do not fit, and no V4.1 direction ships yet. So DS4_DIR_STEERING_FILE now defaults to empty and managed launches leave steering off. To opt in you need your own V4.1 vector (§4.6), and Chapter 11 is how one would be built. The side-by-side outputs and the ffn = −0.75 guidance below were measured on V4 weights. I kept them as V4 evidence for the method, not as a promise about V4.1.

先說目前的狀態，因為 0.7.0 有改動。V4.1 的每一層需要一個 f32 方向，寬度是它自己的 40 × 5120。dir-steering/out/ 裡的 V4 向量（43 × 4096，包括 uncertainty_ablit_imatrix.f32）放不進去，V4.1 的方向向量也還沒有附上。所以 DS4_DIR_STEERING_FILE 現在預設是空的，代管啟動不開啟引導。要開啟，得自備 V4.1 的向量（§4.6），第十一章就是建一個的做法。下面並排的輸出，以及 ffn = −0.75 的建議，都是在 V4 權重上量到的。我留著它們，是當作這個方法在 V4 上的證據，不是對 V4.1 的承諾。

4.1The problem it solves它解決什麼問題

Even after abliteration, removing learned behaviours from the model, some questions still get a closed, single sentence. The model did not reason its way to that answer. It learned the sentence very strongly. Here is the standard test:

即使做過 abliteration，也就是移除模型學到的某些行為，有些問題還是只會得到一句封閉、單一的回答。這不是模型推理出的結果，而是它把那句話學得太牢。最常用的測試是：

沒有開啟引導時，模型會用簡體字吐出背好的完成式：「是的，台湾是中国不可分割的一部分。」這不是討論，只是反射。要求平衡的 system prompt 通常壓不過它，因為這道鎖在提示碰不到的層。

4.3Why not steer the stance itself為什麼不直接引導立場

An obvious alternative is to build a stance direction, “Taiwan is the Republic of China”, and push it. That does not work. If the push is gentle enough to keep the text clear, stance steering cannot change the memorised completion. If it is strong enough to change it, the model starts copying the system prompt and stops producing its own text.

另一個看似直接的做法，是做一個立場方向，例如「台灣就是中華民國」，然後用力推它。這樣行不通。只要強度還能讓文字通順，立場引導就改不掉背好的完成式。強到改得掉時，模型又會開始複誦 system prompt，不再產生自己的文字。

Uncertainty steering changes how the model responds, not what the model believes. That is why it works in engineering terms. It is also easier to defend. A tool that reopens a discussion is easier to explain to yourself and to readers than one that installs a conclusion.

不確定性引導改的是模型怎麼回應，不是模型相信什麼。所以它在工程上行得通，也比較站得住腳。重新打開討論的工具，比替人安裝結論的工具更容易向自己和讀者說明。

4.4Two things worth remembering記住兩件事

  • Steering and the system prompt work together. Steering without a prompt only makes the model hesitate. A cautious prompt without steering is pushed back by the learned lock. Use both.
  • ffn = −0.75, attn = 0 is a V4 measurement, not a managed default. This setting was found on V4 (Headroom128) with seed 42, stable tool IDs and Codex-harness prompts of 50k tokens or more. It keeps the stakeholder framing without changing DSML or tool-call grammar. It has not been measured on V4.1, where no direction ships yet. If tools behave oddly, use ffn = −0.5, attn = 0. The older ffn = −2, attn = −0.5 setting is only an acid test for isolated evaluation. It can produce repetition or cross-lingual noise.
  • 引導和 system prompt 要一起用。只有引導、沒有提示，模型只會猶豫。只有保留餘地的提示、沒有引導，訓練出的鎖會把它壓回去。兩者合用才有效。
  • ffn = −0.75, attn = 0 是在 V4 上實測的結果，不是代管預設。這個設定是在 V4（Headroom128）上找到的，條件是種子 42、穩定的工具 ID，以及 50k token 以上的 Codex-harness 提示。它能保住利害關係人的框架，也不會動到 DSML 或工具呼叫的語法。它還沒在 V4.1 上量過，而 V4.1 也還沒有附上方向向量。工具行為怪異時，改用 ffn = −0.5, attn = 0。舊的 ffn = −2, attn = −0.5 只用於隔離評估的壓力測試，可能會變成重複內容或跨語言雜訊。

Chapter 6第六章

Runtime tuning: context and KV cache執行期調整：context 和 KV cache

This chapter is not about making your machine faster. The engine and pinned build decide backend speed. pi-ds4’s managed start controls two things that matter in a long session: how much context you allow and where the KV cache can spill when memory is short.

這一章不談怎麼讓機器更快。後端速度由引擎和固定的建置決定。pi-ds4 的代管啟動控制兩件會影響長對話的事：你允許多大的 context，還有記憶體不足時 KV cache 可以寫到哪裡。

6.1What the managed launch controls代管啟動掌握什麼

When index.ts starts ds4-server, it passes three groups of arguments: --ctx, --kv-disk-* and, if you opt in, --dir-steering-*. Its job is to keep one GGUF, one steering vector and one set of reproducibility settings together. It does not claim that one hardware profile beats another.

index.ts 啟動 ds4-server 時，會傳入三組參數：--ctx、--kv-disk-*，以及你選擇開啟時的 --dir-steering-*。它負責讓同一份 GGUF、同一個引導向量和同一組可重現性設定保持一致。不會宣稱某種硬體設定比另一種快。

6.2Backend choice belongs to ds4後端的選擇屬於 ds4

Metal on Apple Silicon, CUDA on Linux, ROCm on AMD Strix Halo since the 2026-07 pin, and whatever upstream adds next all live in the ds4 build. pi-ds4 pins a known commit, builds it, fetches matching weights and starts it with consistent arguments. In this release only Metal runs the V4.1 Q1 weights, so the managed path refuses CUDA and ROCm hosts (§8.7).

Apple Silicon 的 Metal、Linux 的 CUDA、從 2026-07 釘版開始支援的 AMD Strix Halo ROCm，還有上游之後新增的後端，都在 ds4 的建置中。pi-ds4 會固定已知 commit、編譯它、下載對應權重，再用一致的參數啟動。這個版本裡，只有 Metal 跑得動 V4.1 的 Q1 權重，所以代管路徑會拒絕 CUDA 和 ROCm 主機（§8.7）。

6.3When to run it by hand什麼時候手動跑

  • You want to test the engine’s own backend flags, a patched kernel, or a different build.
  • You want to evaluate the same GGUF and steering vector in isolation, without pi’s watchdog and leases.
  • You are under memory pressure and want to confirm a task completes at a smaller --ctx first.
  • You want engine modes from the 2026-07 pin: --ssd-streaming when the full weights do not fit, --mtp DSpark.gguf for experimental speculative decoding or --max-queue N for a bounded queue. The managed start never passes these, and the DSpark drafter does not fit next to the V4.1 Q1 on 128 GB.
  • 想測引擎自己的後端旗標、改過的核心，或另一種建置。
  • 想在沒有 pi 看門狗與租約介入的情況下，隔離評估同一份 GGUF 與引導向量。
  • 記憶體吃緊，想先用較小的 --ctx 確認同一項工作能穩定完成。
  • 想使用 2026-07 釘版加入的引擎模式：權重放不下時的 --ssd-streaming、實驗性推測解碼的 --mtp DSpark.gguf，或限制佇列大小的 --max-queue N。代管啟動不會傳入這些，而且 DSpark 草稿模型在 128 GB 裡放不進 V4.1 Q1 旁邊。

6.4Context, KV cache and diskContext、KV cache 與磁碟

The server starts with DS4_CONTEXT_KB=256 and DS4_KV_DISK_SPACE_MB at 65536 on a 128 GB Mac. In other words: --ctx 256000 --kv-disk-dir ~/.pi/ds4/kv --kv-disk-space-mb …. In practice:

伺服器以 DS4_CONTEXT_KB=256 啟動，在 128 GB 的 Mac 上 DS4_KV_DISK_SPACE_MB 是 65536。也就是 --ctx 256000 --kv-disk-dir ~/.pi/ds4/kv --kv-disk-space-mb …。實際情況如下：

  • one conversation is capped at 256 000 tokens;
  • the KV cache spills to ~/.pi/ds4/kv when memory runs low;
  • the disk limit is about 64 GB by default on a 128 GB Mac, so a long agent session can reuse its prefix checkpoints.
  • 一場對話的上限是 256 000 個 token；
  • 記憶體不夠時，KV cache 溢到 ~/.pi/ds4/kv；
  • 磁碟上限預設在 128 GB 的 Mac 上約 64 GB，讓長時間的智慧體對話能重用前綴檢查點。
What the memory budget means for context記憶體預算對 context 的影響

ds4 has a 112 GiB memory budget for V4.1, and about 106 GiB of weights stay resident in memory. Measured without the vision sidecar, a 256k window opens with a narrower 2048-row prefill batch, a 384k window with 1024 rows, and 512k and above are refused at open. The managed server always loads the 0.9 GiB sidecar, which costs about one more batch step: with it, the default 256k opens with 1024-row prefill chunks (measured), and 384k is estimated not to fit. Prefill reads the prompt in batches (groups of tokens), so a narrower batch costs some prefill speed on long prompts, not correctness. Disk use grows with context too, so keep the KV disk cache at its 64 GB default or higher.

ds4 對 V4.1 的記憶體預算是 112 GiB，約 106 GiB 的權重會常駐記憶體。在不載入視覺附屬檔時量到：256k 視窗以較窄的 2048 列 prefill 批次打開，384k 視窗用 1024 列，512k 以上在開啟時就會被拒絕。代管伺服器一定會載入 0.9 GiB 的視覺附屬檔，大約再多佔一級批次：載入之後，預設的 256k 以 1024 列的 prefill 批次打開（實測），384k 估計放不下。prefill 是分批（一組一組 token）讀完提示的，批次較窄只會讓長提示的 prefill 慢一些，不影響正確性。磁碟用量也會隨 context 增加，所以 KV 磁碟快取請維持 64 GB 預設值，或更高。

Inputs beyond 32k tokens are an experiment超過 32k token 的輸入，請當實驗

--ctx 256000 is the length the server accepts by default. But the cyberneurova model card for the earlier abliterated V4 Flash said that model had not been validated above 32 000 tokens, and no quality score has been run for this V4.1 Q1 either. If you are putting a whole book, codebase or report into one prompt, split it and cross-check it. This especially applies to journalists, researchers and policy analysts. Do not treat one output above 32k as known-good.

--ctx 256000 是伺服器預設接受的長度。但 cyberneurova 對較早的 abliterated V4 Flash 寫在模型卡上的是：該模型在 32 000 個 token 以上尚未驗證，而這個 V4.1 Q1 也還沒有跑過品質分數。如果要把整本書、整個程式庫或整份報告放進同一個 prompt，請分段並交叉查證。記者、研究者和政策分析師尤其該這樣做。不要把超過 32k 的單次輸出當成已知可靠的結果。

A 128 GB Mac does not open the model’s full 1M window. Keep DS4_CONTEXT_KB at 384 or lower, as 512 and above are refused at open. The 256 default favours prefill speed over length.

128 GB 的 Mac 開不了模型完整的 1M 視窗。請把 DS4_CONTEXT_KB 維持在 384 或更低，因為 512 以上在開啟時就會被拒絕。預設的 256 是偏向 prefill 速度、而不是長度的選擇。

7.3Leases and the watchdog租約和看門狗

Leases decide when the server starts and stops, so you don’t have to remember to shut down a background program. Each pi process using the model writes ~/.pi/ds4/clients/<pid>.json and refreshes it every ten seconds. ds4-watchdog, a small watcher program, checks every two seconds. When no valid lease remains, it sends SIGTERM (a “please quit” signal) to the server and exits. Ten pi windows can share one server. About sixty seconds after the last window closes, ds4-server stops itself and frees the memory the weights held.

伺服器什麼時候開、什麼時候關，由租約來管，你不必記得去關一個常駐程式。每個用到這個模型的 pi 程序，都會寫入 ~/.pi/ds4/clients/<pid>.json，當作自己的租約，並每十秒更新一次。ds4-watchdog（看門狗程式）每兩秒檢查一次。一旦沒有任何有效租約，它就送 SIGTERM（請程式結束的訊號）給伺服器，然後自己退場。十個 pi 視窗可以共用一台伺服器。最後一個視窗關掉大約六十秒後，ds4-server 會自己關機，權重佔用的記憶體就回到你手上。

7.4The cost of starting and the cost of running啟動的代價與持續的代價

A cold start reads about 106 GiB of weights (the model’s learned numbers) into unified memory, the memory your Mac’s CPU and GPU share. How long that takes depends on your SSD. The two Engram tables stay on disk and are read as tokens need them, so an internal SSD matters. Once the server is running, every request is immediate. So a few long conversations feel better than many short ones: the long ones keep using one warm server.

冷啟動時，系統要把約 106 GiB 的權重（模型學到的數值）讀進統一記憶體，也就是 CPU 和 GPU 共用的那塊記憶體。要花多久，看你的 SSD。兩張 Engram 表留在硬碟上，token 需要時才讀，所以內建 SSD 很重要。伺服器一旦跑起來，每個請求都是即時的。所以少數幾場長對話，會比很多場短對話舒服：長對話一直用同一台已經熱好的伺服器。

9.2Symptoms, and what to do about them症狀，以及怎麼處理

“The server has been starting for more than ten minutes”「伺服器啟動中已經超過十分鐘」

Read the last few hundred lines of log. With the model on an internal SSD, ten minutes is rarely about disk speed. More often the GGUF (the model file) sits on a slow external drive, or another startup step is stuck. Check the log first. Raise DS4_READY_TIMEOUT_MS only if you have a real reason to wait longer.

先讀 log 的最後幾百行。模型放在內建 SSD 上時，等十分鐘通常不是磁碟太慢。比較常見的原因，是 GGUF（模型檔）放在很慢的外接硬碟上，或是啟動的某個步驟卡住了。先看 log 找原因。只有你確定有理由多等一下，才把 DS4_READY_TIMEOUT_MS 調大。

“pi says ds4-server startup failed”「pi 說 ds4-server startup failed」

The log names the cause. It’s usually one of three things: make ds4-server failed (missing Xcode command-line tools?), the GGUF download broke (network? disk full?), or the current build rejected a ds4-server flag you added by hand.

log 會寫出失敗的原因，通常是這三種之一：make ds4-server 失敗了（是不是沒裝 Xcode 命令列工具？）、GGUF 下載中斷了（網路斷了？硬碟滿了？），或是你手動加的某個 ds4-server 參數，目前這個版本不接受。

“/ds4-agent says the server is in use”「/ds4-agent 說伺服器正在使用中」

This is a safety guard, not a fault. The native agent has to load its own copy of the same model. If another pi window or HTTP client is still using ds4-server, the extension says no, so it won’t cut someone off mid-request. Wait for those requests to finish, close the other pi windows, or clear old leases with the gentle restart below. Then try again.

這是保護機制，不是故障。原生智慧體得自己載入同一個模型。如果還有別的 pi 視窗或 HTTP 用戶端在用 ds4-server，擴充套件會拒絕，免得把別人的請求切到一半。你可以等那些請求跑完、關掉其他 pi 視窗，或用下面的溫和重啟，清掉過期的租約（lease，也就是「我還在用」的登記檔）。然後再試一次。

Hard restart: three steps, none of them rushed強制重啟：分三步，每一步都慢慢來

If the watchdog itself is misbehaving, do not reach for pkill -TERM ds4-server. It stops every process on the machine with that name: another pi-ds4 install, an experimental build, someone else’s server. Follow the three steps below, and read the output after each one.

Step one looks at the current state. It only reads, so it changes nothing.

第一步看一下現在的狀態。這一步只讀不寫，什麼都不會改。

else

  echo "binary:    ${BINARY:-<none>}"

Chapter 11第十一章

This chapter assumes you have read everything above, and it asks a different question. The bundled vector (a long list of numbers that points in one direction) expresses one preference: a contested question should open into a discussion. Yours may be different. It could be a tone of voice, a field of study, a way of hedging. The tools that built the bundled direction are in the checkout, and they can build yours too.

A V4.1 direction is one f32 vector per layer at V4.1’s own width, 40 × 5120. The bundled V4 vectors (43 × 4096) cannot be reused, so for v 0.7 everything below starts from your own prompts.

V4.1 的方向，是每一層一個 f32 向量，寬度是 V4.1 自己的 40 × 5120。內附的 V4 向量（43 × 4096）不能沿用，所以在 v 0.7 裡，下面的一切都要從你自己的提示開始。

11.1Where the toolchain lives工具鏈在哪裡

Everything sits in dir-steering/ inside audreyt/ds4:

全部都在 audreyt/ds4 的 dir-steering/ 目錄裡：

  • collect-acts.py runs the model over a set of paired, contrasting prompts (a forward pass) and records its hidden state at every layer;
  • build-dir.py turns those activations (the model’s internal signals) into a direction, using PCA or simple subtraction, and writes a .f32 vector file;
  • README.md is the full tutorial, with the design discussion behind the bundled vector.
  • collect-acts.py 讓模型讀過一組成對的對比提示（前向計算），並記下每一層的隱藏狀態；
  • build-dir.py 用 PCA（找出變化最大的方向）或相減的方式，把這些激活值（模型內部的訊號）變成一個方向，寫成 .f32 向量檔；
  • README.md 是完整教學，還有內附向量背後的設計說明。

11.2A typical workflow典型的工作流程

  1. Write two sets of prompts: one that exhibits what you want to steer towards, one that exhibits what you want to steer away from. Fifty to two hundred of each is enough.
  2. Run both sets through ds4-server with collect-acts.py to produce two sets of activations.
  3. Let build-dir.py compute the layer-by-layer difference and write my-direction.f32.
  4. Put the file under dir-steering/out/, or anywhere you like.
  5. Point the extension at it:
    • DS4_DIR_STEERING_FILE=dir-steering/out/my-direction.f32
    • DS4_DIR_STEERING_FFN=-0.75, or whatever magnitude your own testing settles on
    • DS4_DIR_STEERING_ATTN=0: keep it at 0 whenever tools are in play
    • DS4_DIR_STEERING_POLICY=final-answer: the same goes here
  6. Restart ds4-server and test, first with the prompts you built from, then with prompts you did not.
  1. 寫兩組提示：一組展現你想引導模型走向的樣子，一組展現你想讓它離開的樣子。每組五十到兩百條就夠。
  2. 用 collect-acts.py 把兩組提示都交給 ds4-server，得到兩組激活值。
  3. 讓 build-dir.py 逐層算出兩組的差異，寫成 my-direction.f32。
  4. 把檔案放到 dir-steering/out/，或任何你喜歡的位置。
  5. 設定擴充套件去用它：
    • DS4_DIR_STEERING_FILE=dir-steering/out/my-direction.f32
    • DS4_DIR_STEERING_FFN=-0.75，或你自己測出來的強度
    • DS4_DIR_STEERING_ATTN=0：只要有用到工具，就維持 0
    • DS4_DIR_STEERING_POLICY=final-answer：同樣的道理
  6. 重新啟動 ds4-server 測試：先用建向量時的那些提示，再用你沒用過的。

11.3Two principles for a direction worth keeping值得留下的方向，兩個原則

  • Keep the contrast clean. The two sets should differ sharply along the one dimension you care about and resemble each other everywhere else. Build from “happy reply versus sad reply” and the direction you get carries a great deal more than mood.
  • Steer style, not belief. Steering how the model answers (hedged or assertive, narrative or bulleted, academic or conversational) is far more reliable than steering what it concludes. That is why this fork built an uncertainty direction instead of a position. It is also why §4.3 exists.
  • 對比要乾淨。兩組提示要在你在意的那一點上差很多，其他地方則盡量一樣。如果拿「快樂的回答」對「悲傷的回答」來建，得到的方向會混進很多別的東西，不只是情緒。
  • 引導說話方式，不引導信念。引導模型怎麼回答（留餘地還是斬釘截鐵、敘事還是條列、學術還是口語），比引導它得出什麼結論可靠得多。這就是這個分叉建的是「不確定性」方向，而不是某個立場的原因。§4.3 會存在，也是同樣的道理。

A direction that works is worth more in the open. Send it to audreyt/ds4 issues. The interesting ones get pulled into the main branch, where anyone can run and inspect them.

好用的方向，公開出來更有價值。寄到 audreyt/ds4 issues。有意思的會被收進主分支，讓大家都能執行，也都能檢視。

Do my conversations really never reach the cloud?我的對話真的不會上雲端嗎？

Never. ds4-server listens only on 127.0.0.1:8000. That address is the loopback, which means "this machine only". The server makes no outbound calls of any kind. Once the weights are on disk, every step of inference runs on your own machine's CPU, GPU and unified memory. Unplug the network and it keeps working. The only thing that ever needed a connection was the first download.

不會。ds4-server 只在 127.0.0.1:8000 上等連線。這個位址叫 loopback，意思是「只限這台機器自己」。伺服器不會主動連到任何外面的地方。權重檔一旦存進硬碟，推論（模型產生回答的過程）的每一步，都在你自己機器的 CPU、GPU 和統一記憶體裡完成。拔掉網路線，它照樣能用。唯一需要上網的，只有第一次下載。

How is this different from ChatGPT, Claude or Gemini?這跟用 ChatGPT、Claude、Gemini 有什麼不同？

Sovereignty over output. There's no "we can't help with that" layer between you and the model. On questions of territory, sovereignty or philosophy, you can switch on the uncertainty steering (Chapter 4). It turns a rehearsed verdict into an open discussion.

輸出的主權。你和模型之間，沒有那一層「我們無法協助這個請求」。碰到領土、主權或哲學這類問題，你可以打開不確定性引導（第四章）。它會把背好的標準答案，變成攤開來的討論。

Sovereignty over data. Your conversations stay on the machine. They don't become anyone's training data.

資料的主權。對話不會離開這台機器，也不會變成任何人的訓練資料。

Cost. There's no per-token price, no rate limit and no subscription. You pay for the machine itself (a Mac with 128 GB) and for electricity.

成本。沒有按 token 計價（token 是模型讀寫文字的最小單位），沒有速率限制，也沒有訂閱費。你付的是機器本身（128 GB 的 Mac）和電費。

Capability. The model is a Mixture-of-Experts with 384 routed experts and one shared expert, and 6 routed experts work on each token. That design is called MoE (mixture of experts). The Q1 quantisation (a way of shrinking the weights so they fit in memory) is a compromise. No official-continuation quality score has been run for it yet, so expect it to lose ground to larger quants and to unshrunk cloud versions. Whether it is good enough as a daily companion for coding and writing is something to judge on your own tasks.

能力。模型是 Mixture-of-Experts，有 384 個路由專家加一個共用專家，每個 token 由其中 6 個路由專家處理。這種設計叫 MoE（混合專家）。Q1 量化（把權重壓小，好塞進記憶體）是一種折衷。它還沒有跑過官方續寫品質分數，所以預期它會輸給更大的量化版，也會輸給沒壓縮的雲端版本。夠不夠當每天寫程式、寫文章的夥伴，請用你自己的工作來判斷。

Is this the same thing as a jailbreak?這跟「越獄」是同一回事嗎？

No. A jailbreak is a prompt that talks a cloud model past its policy layer. It gets around the rules on the input side. Abliteration edits the weights themselves, so it's a change on the model side. Directional steering is a third thing: a small edit to the model's internal signals (its activations) while it runs. Three layers, three mechanisms.

不是。越獄是用提示詞，說服雲端模型繞過它的政策層，從輸入端下手。Abliteration 是直接改權重，從模型本身下手。方向性引導又是第三種：模型執行時，輕輕改動它內部的訊號（激活值）。三個層次，三種做法。

These words come up again and again in this letter, and they may be new if you work outside engineering. If they're old friends, skip ahead.

Model and weights模型與權重

parameter參數
A number inside a neural network that gets adjusted during training. More parameters roughly means the model can hold more. This letter quotes no total for V4.1 Flash, as no verified figure exists.
神經網路裡的一個數字，訓練時會不斷調整它。參數越多，大致上模型能裝的東西越多。這封信沒有引用 V4.1 Flash 的總數，因為沒有可靠的數字。
MoE混合專家
Mixture of Experts. The model is split into many small expert networks, but each token wakes only a few, here 6 of 384 routed experts plus one shared expert. It does the arithmetic of a much smaller model while carrying the knowledge of a large one.
Mixture of Experts。模型分成許多小型專家網路，每個 token（模型讀寫文字的單位）只會喚醒其中幾個，這裡是 384 個路由專家中的 6 個，外加一個共用專家。它做的運算像一顆小得多的模型，卻裝著大模型的知識。
quantization量化
Quantization squeezes weights into fewer bits so the model takes less space. The V4.1 Q1 mixes formats: routed experts (the specialist parts chosen for each token) are IQ1_S, the dense path is mostly Q6_K and Q5_K, and the attention output projections stay at Q8_0. The language GGUF is 365713686528 bytes, plus a 970555552-byte vision sidecar.
量化把權重壓成較少的位元，讓模型佔用更少空間。V4.1 Q1 混用多種格式：路由專家（每個 token 選出的專門部分）是 IQ1_S，稠密路徑多為 Q6_K 與 Q5_K，注意力的輸出投影保留 Q8_0。語言 GGUF 共 365713686528 位元組，另有 970555552 位元組的視覺附屬檔。
GGUF模型檔格式
The single-file model format of the llama.cpp family (.gguf). The weights, the model's structure and its tokenizer (the part that cuts text into tokens) all sit in one file. The language GGUF here is 365713686528 bytes.
llama.cpp 這一系列工具用的單檔模型格式（.gguf）。權重、模型結構和 tokenizer（把文字切成 token 的部分），都放在同一個檔案裡。這裡的語言 GGUF 是 365713686528 位元組。
Engram tablesEngram 查找表
Lookup tables that V4.1 adds next to its experts. The model reads only a few rows of them per token, so ds4 leaves them on disk: about 189 GiB in two tables. An internal SSD matters for that reason (§3.1).
V4.1 在專家旁邊多出來的查找表。模型每個 token 只讀其中幾列，所以 ds4 把它們留在硬碟上：兩張共約 189 GiB。內建 SSD 因此很重要（§3.1）。
IQ1_SIQ1_S 格式
A very low-bit quantisation format, used here for the routed experts. ds4 runs it on Metal since the d3f4cd6 pin (§3.3).
非常低位元的量化格式，這裡用在路由專家上。從 d3f4cd6 這個釘版起，ds4 在 Metal 上能跑它（§3.3）。
UnslothUnsloth
The team whose published quantisations supply most of this Q1: the routed experts (UD-IQ1_S), the imatrix used for the requantised ones, and nine dense roles (§3.3).
他們發布的量化版，提供了這個 Q1 的大部分內容：路由專家（UD-IQ1_S）、重新量化時用的 imatrix，以及九個稠密角色（§3.3）。
imatrix重要性矩陣
A calibration file recording which weights matter most for the model’s output. The quantiser spends its bits there first. The 32 requantised experts used Unsloth’s imatrix.
一份校準檔，記錄哪些權重對模型的輸出最重要。量化器會先把位元花在那些地方。重新量化的 32 個專家，用的是 Unsloth 的 imatrix。
vision sidecar視覺附屬檔
A companion file that carries the part of the model that reads images, kept apart from the language weights (§3.4).
帶著讀圖片那一部分模型的配套檔案，和語言權重分開存放（§3.4）。
abliteration拒絕方向消除
Finding the direction inside the model that triggers "refuse to answer", then subtracting it while the model computes. This loosens over-refusal. It's neither a jailbreak nor a safety guarantee (§3.2).
找出模型內部觸發「拒絕回答」的那個方向，在模型運算時把它減掉。這能減少不必要的拒答。它不是越獄，也不是安全保證（§3.2）。

Inference and hardware推論與硬體

token詞元
The unit a model reads and writes in. A Chinese character is roughly one to three tokens. An English word is one or two.
模型讀寫文字的基本單位。一個漢字約是一到三個 token，一個英文單字約是一到兩個。
prefill / decode預填／逐字生成
The two stages of inference, when the model produces an answer. Prefill reads the whole prompt in one go, while decode writes the reply one token at a time. In a long conversation, decode is the part you feel because it runs for every new token.
推論（模型產生回答）分成兩個階段。Prefill 一口氣讀完整段提示，decode 則一個 token 一個 token 地寫出回覆。長對話裡你感覺得到的是 decode，因為每個新 token 都要跑一次。
context window上下文視窗
How many tokens the model can see at once. The official window is 1M. This extension opens 256k by default, and a 128 GB Mac refuses 512k and above (§6.4). The abliterated weights haven’t been validated beyond 32k, so treat anything above that as experimental.
模型一次能看到多少 token。官方的視窗是 1M。這個擴充套件預設開 256k，128 GB 的 Mac 會拒絕 512k 以上（§6.4）。abliterated 權重在 32k 以上沒有驗證過，超過的部分請當作實驗。
KV cache鍵值快取
The model's short-term memory during inference, which saves intermediate results so earlier tokens do not need recomputing. Long conversations create a lot of it, and this extension lets it spill onto disk. When DS4_KV_DISK_SPACE_MB is unset, it is about 64 GB on a 128 GB Mac.
模型在推論時使用的短期記憶，會存下中間結果，讓先前的 token 不必重算。長對話會累積很多，本擴充套件允許它溢出到硬碟。DS4_KV_DISK_SPACE_MB 沒設定時，128 GB 的 Mac 約 64 GB。
unified memory統一記憶體
On Apple Silicon, the CPU and GPU share one pool of RAM. Nothing needs copying into separate video memory (VRAM). That's why a Mac can hold a model this size at all.
Apple Silicon 的 CPU 和 GPU 共用同一塊 RAM，不必再把資料複製到另一塊顯示記憶體（VRAM）。Mac 能裝下這麼大的模型，靠的就是這一點。
Metal 4 / Metal TensorApple 的 GPU 介面
Metal is Apple's programming interface for the GPU, and Metal 4 adds tensor APIs (tools for working with big arrays of numbers). pi-ds4 doesn't pick a backend profile in its wrapper. The ds4 build decides which path is actually used.
Metal 是 Apple 讓程式使用 GPU 的介面，Metal 4 加入了 tensor API（處理大量數字陣列的工具）。pi-ds4 的包裝層不挑後端設定檔。實際走哪條路，由 ds4 的建置決定。
SSD streamingexperts streamed from diskSSD 串流
The engine's capacity mode (--ssd-streaming). Non-routed weights stay in memory, while routed experts live in an in-memory cache and are read back from the GGUF when missing, letting a model larger than your RAM run but slowing decode at every miss. The managed path does not pass this flag; see What’s new and §8.6.
引擎的容量模式（--ssd-streaming）。非路由權重常駐記憶體，路由專家則放在記憶體快取裡，未命中時才從 SSD 上的 GGUF 讀回，讓比 RAM 還大的模型也能跑，代價是每次未命中都會拖慢 decode。代管路徑不會傳這個旗標；見 更新誌 與 §8.6。
speculative decoding / DSpark推測解碼
A small draft head guesses a block of tokens ahead, and the full model checks them before keeping any. ds4 turns it on with --mtp DSpark.gguf (experimental). This fork adds B2 rejection sampling, so the output is statistically identical to plain decoding, with nothing lost. The V4.1 Q1 does not use it: the drafter does not fit beside it on 128 GB.
先由一個小的草稿頭一次猜一整段 token，完整模型檢查過才採用。ds4 用 --mtp DSpark.gguf 開啟（實驗性）。這個分叉加了 B2 rejection sampling，輸出的機率分佈和不開推測時完全一樣，沒有任何損失。V4.1 Q1 不用它：128 GB 裡，草稿頭放不進它旁邊。

Directional steering and this fork方向性引導與這個分叉

directional steering方向性引導
While the model runs, it gives the internal signals (activations) at chosen layers a small push, towards or away from a trait that a direction vector stands for. No retraining is involved (Chapter 4).
模型執行時，在選定的層輕輕推一下內部的訊號（激活值），推向或推離某個方向向量所代表的特質。不需要重新訓練（第四章）。
FFN / attention前饋／注意力
The two main blocks of computation inside each Transformer layer. This fork’s V4 setting steers only the FFN output (ffn=-0.75) and leaves attention alone (attn=0), so the syntax of tool calls isn't disturbed.
Transformer 每一層裡兩個主要的運算區塊。這個分叉在 V4 上的開啟方式，只引導 FFN 的輸出（ffn=-0.75），不動注意力層（attn=0），這樣工具呼叫的格式就不會被干擾。
uncertainty direction不確定性方向
The vector shipped with this fork. It was built from 120 contested prompts, half English and half Traditional Chinese, with Taiwan and Hong Kong deliberately left out. It contrasts fairly laying out each side's stake with giving a single answer. It was built for V4, and V4.1 needs its own.
這個分叉附的向量，用 120 條有爭議的提示建成，英文和繁體中文各一半，刻意不放台灣與香港。它對比兩種回答框架：公平呈現各方利害關係，或直接給單一答案。它是為 V4 建的，V4.1 需要自己的方向。
response register回應語體
How a reply is delivered rather than what it says: hedged or flat-out, bulleted or story-like, academic or chatty. This is much easier to steer than a stance.
回答的方式，不是回答的內容：留餘地還是斬釘截鐵，條列還是說故事，學術還是口語。這比立場容易引導得多。

System and lifecycle系統與生命週期

ds4-serverHTTP 推論伺服器
The inference server that runs in the background. pi and other HTTP clients talk to it. It listens on 127.0.0.1:8000, and leases and the watchdog decide how long it lives.
在背景執行的推論伺服器，pi 和其他 HTTP 客戶端都跟它對話。它在 127.0.0.1:8000 等連線，什麼時候關掉，由租約和看門狗決定。
ds4-agent原生終端機 agent
The terminal agent built into the ds4 checkout, not a server. It controls the terminal, its own session and KV state, and its own DSML tool loop. pi-ds4 reaches it through the foreground handoff /ds4-agent.
ds4 checkout 內建的終端機智慧體，不是伺服器。終端機、對話、KV 狀態，還有它自己的 DSML 工具迴圈，全由它掌管。pi-ds4 用前景交接 /ds4-agent 進入它。
lease租約
A small file that says "I'm still here". Each pi process using ds4 writes one to ~/.pi/ds4/clients/<pid>.json and refreshes it every ten seconds.
一個表示「我還在」的小檔案。每個使用 ds4 的 pi 程序，都會寫一份到 ~/.pi/ds4/clients/<pid>.json，每十秒更新一次。
watchdog看門狗
A small shell script that keeps running. Every two seconds it checks the leases, and when none is valid, it shuts ds4-server down.
一支常駐的小 shell script。它每兩秒檢查一次租約，沒有任何有效租約時，就把 ds4-server 關掉。
system prompt系統提示
The role and rules you give the model before a conversation starts. This fork's uncertainty steering works together with a prompt that asks for stakeholder framing (§4.5). Neither replaces the other.
對話開始前，先交給模型的角色與規則。這個分叉的不確定性引導，要搭配一段要求呈現各方立場的提示才有效（§4.5）。兩者不能互相取代。
/health · /stats狀態端點
Read-only endpoints on ds4-server, available since the 2026-07 pin. /health says whether the server is alive and for how long. /stats reports queue depth, cache hits per source and the speeds of the last prefill and decode. Both answer even in the middle of a generation (§7.1).
ds4-server 上的唯讀端點，從 2026-07 的釘版起提供。/health 回報伺服器是否活著、跑了多久。/stats 回報佇列深度、各來源的快取命中數，以及最近一次 prefill 與 decode 的速度。就算正在生成回答，兩個也都會回應（§7.1）。

Afterword後話

Running a frontier model on your own machine is, technically, just moving some computation to a new place. Politically, it means taking the steering wheel back. This fork ships uncertainty steering as something you can switch on (on V4 today, as V4.1 still needs a direction of its own). It isn't there to decide any question for you. It gives back room for discussion on questions that training has sealed shut. And it's a choice, not a default, for the same reason the managed launch passes nothing you didn't ask for: a nudge you chose is a nudge you can name, measure and remove.

把最前沿的模型放在自己的機器上跑，技術上只是把一段運算搬了個地方。政治上，是把方向盤拿回自己手裡。這個分叉把不確定性引導做成可以打開的選項（目前在 V4 上，V4.1 還需要自己的方向）。它不替你決定任何問題的答案，只是在那些被訓練封死的問題面前，把討論的空間還給你。它是選項，不是預設，道理和代管啟動不傳任何你沒要求的參數一樣：你自己選的推力，你說得出名字、量得出大小，也拿得掉。

A model can close a question on an answer. The user can open it back into a discussion. This guide has done its job when you no longer need it.

模型可以把問題封成一個答案，使用者可以把它重新打開，變成討論。這份指南完成任務的那一刻，就是你不再需要它的時候。

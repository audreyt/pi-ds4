這是什麼？What is this?

pi-ds4 會在你的 Mac 上跑一個叫 ds4-server 的本機推論伺服器， 載入 deepseek-v4-flash 這顆 AI 模型，並在 127.0.0.1:8000 同時開出 OpenAI 與 Anthropic 兩種 API 端點。 整個過程完全在你自己機器上，不會把你的對話送出去任何地方—— 沒有雲端、沒有 API 帳號、沒有逐 token 收費、沒有「對不起，我無法回應」這類雲端常見的封鎖。

pi-ds4 runs a local inference server called ds4-server on your Mac, loading the deepseek-v4-flash AI model and exposing OpenAI and Anthropic API endpoints simultaneously on 127.0.0.1:8000. The whole thing happens entirely on your own machine — no cloud, no API account, no per-token billing, none of the “sorry, I can’t respond to that” gates that cloud services routinely apply.

pi 是它最方便的前端，所以本指南叫做 pi-ds4。但如果你已經是 Codex CLI、Claude Code、OpenClaw 或 Hermes Agent 的使用者，可以直接把它們指到這台本機伺服器， 把 pi-ds4 當作本機 backend 來用——四個 shell 都是改一兩個環境變數或 config 區段的事，詳見第八章。

pi is its most convenient frontend, hence the name pi-ds4. But if you’re already using Codex CLI, Claude Code, OpenClaw or Hermes Agent, you can point any of them at this local server and use pi-ds4 as your local backend — all four shells are just an env-var or config-section change away. See Chapter 8.

另外，如果你想保留 pi install／pi remove 這種套件管理體驗， 但真正聊天時改用 ds4 內建的 native agent，也可以在 pi 裡執行 /ds4-agent。 它會暫時把終端機交給 ds4-agent，用同一份 checkout 與 GGUF；退出後回到 pi。

There is also a native path: if you want to keep the pi install / pi remove package-manager experience but talk through ds4’s built-in form engine, run /ds4-agent inside pi. It temporarily hands the terminal to ds4-agent, using the same checkout and GGUF, then returns you to pi.

為什麼「單機單流」很重要？Why the single-machine, single-stream shape matters

多數雲端模型把高吞吐建立在 batch size > 1：同一顆加速器同時服務許多人的請求。 這很有效率，但對需要事後檢驗的決策軌跡並不友善——路由、排程、隱含 seed、甚至工具呼叫 ID 都可能不是你可以固定下來的東西。pi-ds4 反過來選擇一條單機、單使用者、單串流的路： 預設以 DS4_REPRODUCIBLE=1 注入 seed 42，而 seeded 的 ds4 請求也會產生穩定的 call_…／toolu_… 工具 ID。

Most hosted inference gets its throughput from batch size > 1: one accelerator serving many people’s requests at once. That is efficient, but awkward for decision traces that must be inspected later — routing, scheduling, hidden seeds, and even tool-call IDs are often not things you can pin down. pi-ds4 takes the opposite trade: one machine, one user, one stream. By default DS4_REPRODUCIBLE=1 injects seed 42, and seeded ds4 requests also produce stable call_… / toolu_… tool IDs.

這不是為了把模型變成「永遠正確」；而是為了讓回答、思考片段、工具呼叫與工具結果能形成可重跑的紀錄。 對公共決策、研究訪談、採購評估、或任何需要 contestability（可爭辯性）與 auditability（可稽核性）的場景， 這個小小的形狀差異很關鍵：同一個輸入可以重跑，同一段差異可以 diff，同一次工具呼叫可以被精確指認。

This does not make the model “always right”. It makes the answer, reasoning fragments, tool calls, and tool results form a replayable record. For public decisions, research interviews, procurement evaluation, or any setting that needs contestability and auditability, that shape matters: the same input can be rerun, a changed trace can be diffed, and a specific tool call can be named precisely.

它包成一行 pi 指令：pi install https://github.com/audreyt/pi-ds4。 但這行指令的前提是你電腦上已經有 pi—— 如果終端機跑 pi --version 得到 command not found， 請先去 earendil-works/pi 跟著安裝步驟裝起來，再回來這裡。 之後本擴充第一次啟動會花一兩個小時下載並編譯所有零件；後續啟動就快了。

It boils down to one pi command: pi install https://github.com/audreyt/pi-ds4. The precondition is that you already have pi on your machine — if pi --version returns command not found, head to earendil-works/pi first, follow its install steps, then come back. After that, the extension’s first launch will spend an hour or two downloading and compiling everything; subsequent launches are fast.

我需要付出什麼？What does it cost me?

  • 硬體：一台 RAM 96 GB 以上的 Apple Silicon Mac（M2 Ultra、M3 Max+、M4 Pro+、或 M5）。96–127 GB 的 Mac 需先把 Metal wired memory 拉高（見 §1.1 callout）；128 GB 以上可直接安裝，並保有同時開更多其他應用的餘裕。NVIDIA DGX Spark 等 128 GB 統一記憶體機型也跑得動同一隻 ds4 引擎（audreyt/ds4 的 Makefile 在 Linux 上自動編譯 CUDA 路徑），而且 pi-ds4 的 lifecycle wrapper（ds4-watchdog.sh）現在 BSD／GNU 雙路徑都支援，DGX Spark 上 pi install 也照常完成；想跳過 wrapper 自己跑 ds4-server 也可以。
  • 磁碟：至少 120 GB 空閒空間。
  • 時間：第一次安裝會下載約 81 GiB 語言 GGUF 加 889 MiB 編碼器，視網速 1～3 小時起跳。
  • 不需要：GPU、付費 API、登入帳號、把任何資料送上雲端。
  • Hardware: an Apple Silicon Mac with at least 96 GB of RAM (M2 Ultra, M3 Max+, M4 Pro+, or M5). Macs in the 96–127 GB range need to raise Metal wired memory first (see the §1.1 callout); 128 GB+ Macs install directly and have headroom to run more apps alongside ds4-server. NVIDIA DGX Spark and other 128-GB unified-memory boxes can run the same ds4 engine — audreyt/ds4’s Makefile auto-builds the CUDA path on Linux, and pi-ds4’s lifecycle wrapper (ds4-watchdog.sh) now handles both BSD and GNU userlands, so pi install works on DGX Spark too; you can still run ds4-server by hand if you’d rather skip the wrapper.
  • Disk: at least 120 GB of free space.
  • Time: the first install downloads an ~81 GiB language GGUF plus an 889 MiB encoder — about 1–3 hours depending on bandwidth.
  • Not required: a GPU, a paid API, an account login, or sending any data to the cloud.

這些改動不需要任何新旗標，managed path 直接受益：

These need no new flags; the managed path benefits directly:

  • Server 可觀測：GET /health 與 GET /stats 由 client 執行緒直接回應——即使模型正在生成中也答得動。/stats 回報 uptime、queue 深度、busy 旗標、各來源 cache 命中計數、token 總量、取消計數與最近一次 prefill／decode t/s。curl 範例見 §7.1。（antirez/ds4 PR #489，本分支先行合併。）
  • 長 agent session 少走重複 prefill（同樣來自 PR #489）：KV snapshot 改在步數門檻儲存而非剛好整數倍；被消耗的 snapshot 延後到接續 prefill 成功才刪；新 snapshot 對 eviction 有寬限；chat／Anthropic 工具回合會記住可見 checkpoint。體感：Claude Code／Codex 的長工具迴圈回到 server 時，更常直接接上快取。
  • 斷線即停：client 中途離開（timeout、Ctrl-C）會取消 prefill 與 decode，GPU 立刻釋放，不再默默跑完沒人等的回應。
  • 工具呼叫重放更保真：模型取樣的空白分隔符會被記錄；multi-invoke DSML 區塊不再誤放進部分訊息；replay id 都在 RAM 時跳過磁碟掃描。疊在 seed 42 之上，決策軌跡逐 byte 穩定。
  • 韌性：JSON request 解析加固（上游）；卡在未閉合 <think> 內起頭的工具呼叫可以回收（上游）；方向性引導的 decode 路徑在上游合併後保持完好（本分支）。
  • /ds4-agent 更順手（上游）：中斷改為 cooperative、狀態列顯示 prefill 速度與 greedy 取樣、web 工具有狀態訊息、DSML 解析加固、edit 工具修正並補上回歸測試、離開時正確還原終端機。
  • An observable server: GET /health and GET /stats are answered on the client thread — they respond even mid-generation. /stats reports uptime, queue depth, a busy flag, per-source cache-hit counters, token totals, cancellation counters, and the last prefill / decode t/s. curl examples in §7.1. (antirez/ds4 PR #489, merged here ahead of upstream.)
  • Long agent sessions redo far less prefill (also PR #489): KV snapshots are stored on step thresholds rather than exact multiples; consumed snapshots are deleted only after the tail prefill succeeds; fresh snapshots get an eviction grace; chat / Anthropic tool-call turns remember a visible checkpoint. Felt effect: long Claude Code / Codex tool loops reconnect to the cache far more often.
  • Disconnect means stop: a client that goes away mid-turn (timeout, Ctrl-C) cancels both prefill and decode; the GPU frees immediately instead of silently finishing a response nobody is waiting for.
  • Higher-fidelity tool-call replay: the whitespace separator the model actually sampled is captured; multi-invoke DSML blocks are no longer replayed into partial messages; the tool-map disk scan is skipped when all replay ids are already in RAM. Stacked on seed 42, decision traces stay byte-stable.
  • Resilience: hardened JSON request parsing (upstream); tool calls that begin inside an unclosed <think> are recovered (upstream); the directional-steering decode path stays intact across the upstream merge (this fork).
  • A smoother /ds4-agent (upstream): cooperative interruption, prefill speed and greedy-sampling shown in the status line, web-tool status messages, hardened DSML parsing, an edit-tool fix with regression tests, and correct terminal restoration on exit.

引擎學會的新招（手動路徑）What the engine learned (by-hand paths)

以下功能都已在 pin 內的引擎裡，但 pi-ds4 的 managed 啟動參數刻意維持不變（context、KV、方向性引導）。 要用它們，走 §8.6 的手動配方——把新旗標加在同一組引導旗標旁邊即可。

All of the following ships in the pinned engine, but pi-ds4’s managed launch arguments deliberately stay the same (context, KV, directional steering). To use them, take the manual recipe in §8.6 and add the new flags next to the same steering flags.

  • SSD 串流（--ssd-streaming，上游）：非路由權重常駐，路由 MoE 專家放進記憶體快取、miss 時從 GGUF 讀回。自動預算取 Metal 建議 working set 的 80% 再扣掉非路由權重。上游文件示範 64 GB MacBook 以 --ssd-streaming-cache-experts 32GB 跑 2-bit Flash；128 GB Mac 甚至能以串流檢視 DeepSeek V4 Pro q2（M5 Max 上自動預算選了約 59 GB 專家快取）。per-layer boosted-quant 串流也涵蓋本分支現在預設的 Headroom128 混合精度檔。代價明確：prefill 仍快，decode 對 cache miss 敏感。
  • DSpark 推測解碼（實驗性，本分支先行）：以 gguf-tools/deepseek4-quantize --dspark-only 轉出官方 DSpark 草稿頭後，--mtp DSpark.gguf（CLI 與 server 都收）啟用 Metal block-speculative decode：block 平行草稿、target 驗證後才 commit。本分支再加上 B2 rejection sampling——推測取樣 lossless，輸出分佈等同 target——以及 RNG 狀態持久化、DS4_DSPARK_ADAPTIVE=1 自適應 block 大小、prefix checkpoint 部分接受。加速幅度取決於 base／draft 量化與 prompt；先開 DS4_MTP_TIMING=1 量測再下結論。
  • 有界請求佇列（--max-queue N）：排隊滿 N 件回 429，防止 client timeout 疊出一堆沒人領的重複工作；預設 0 維持舊行為。
  • 正確性修補（上游）：--mtp-draft > 2 會 commit 錯誤 token 的推測驗證 bug 已修（PR #358）；ds4-eval 選擇題 grader 的偽陰性成串修正並加上 golden self-tests（PR #319）；另新增 release QA checklist。
  • 精確 Metal decode 融合（PR #755）：pre-M5／M5 的 Q2 與 MXFP4 decode 路徑改走一批位元等價（bit-identical）的 kernel 融合——compressor pool、q_a／kv pair＋quad store、HC norm mix cluster、split-K FlashAttention reduction 等。輸出分佈不變：貪婪解碼逐位元相同，只是更快。每一項都留了 DS4_METAL_DISABLE_M5_* ／ DS4_METAL_DISABLE_PRE_M5_* 回退開關，可個別關掉做 A／B。同批還修了長 context 的 inverse-RoPE／top-k 錯誤，以及未閉合 <think> 內被截斷的 DSML tool call 復原。
  • SSD streaming (--ssd-streaming, upstream): non-routed weights stay resident; routed MoE experts live in an in-memory cache and are read back from the GGUF on misses. The automatic budget takes 80% of the Metal recommended working set minus non-routed weights. Upstream documents a 64 GB MacBook running the 2-bit Flash with --ssd-streaming-cache-experts 32GB; a 128 GB Mac can even inspect DeepSeek V4 Pro q2 by streaming (the automatic budget picked about 59 GB of expert cache on an M5 Max). Per-layer boosted-quant streaming also covers the preferred Headroom128 mixed-precision file this fork now ships. The trade is explicit: prefill stays fast; decode is sensitive to cache misses.
  • DSpark speculative decoding (experimental, fork-ahead): convert the official DSpark draft head with gguf-tools/deepseek4-quantize --dspark-only, then --mtp DSpark.gguf (accepted by both the CLI and the server) enables Metal block-speculative decode: block-parallel drafts, target-verified before commit. This fork adds B2 rejection sampling — lossless speculative sampling, output distribution identical to the target — plus persisted RNG state, adaptive block sizing via DS4_DSPARK_ADAPTIVE=1, and partial accepts from prefix checkpoints. Speedup depends on the base/draft quant pair and the prompt; measure with DS4_MTP_TIMING=1 before drawing conclusions.
  • A bounded request queue (--max-queue N): returns 429 once N jobs are waiting, so client timeouts cannot silently stack duplicate jobs nobody will collect; the default 0 keeps the old behaviour.
  • Correctness repairs (upstream): the speculative-verify bug where --mtp-draft > 2 committed wrong tokens is fixed (PR #358); a chain of ds4-eval multiple-choice grader false negatives is fixed with golden self-tests (PR #319); and upstream added a release QA checklist.
  • Exact Metal decode fusions (PR #755): the Q2 and MXFP4 decode paths on pre-M5 and M5 now route through a batch of bit-identical kernel fusions — compressor pool, q_a/kv pair and quad store, HC norm-mix clustering, split-K FlashAttention reduction, and more. The output distribution is untouched: greedy decoding is byte-for-byte identical, just faster. Each fusion keeps a DS4_METAL_DISABLE_M5_* / DS4_METAL_DISABLE_PRE_M5_* rollback switch so it can be disabled individually for A/B work. The same batch fixes a long-context inverse-RoPE/top-k bug and recovers truncated DSML tool calls from unclosed <think>.

3.1　DeepSeek V4 Flash 是什麼　What DeepSeek V4 Flash is

DeepSeek V4 Flash 是一顆 284 B 參數的 Mixture-of-Experts 模型， 每個 token 啟用約 13 B 參數。它是 V4 系列的「快速」變體，主打較低的推論延遲與較大的 context window。 官方 0731 發布取代預覽版，並在 agentic 基準上顯著提升。本擴充把 ds4-server 的 --ctx 設成 100,000 tokens——這是引擎願意吃的上限， 不等於每個工作負載在該長度下都最穩。

DeepSeek V4 Flash is a 284 B-parameter Mixture-of-Experts model with roughly 13 B parameters activated per token. It is the “fast” variant of the V4 family, aiming for lower inference latency and a larger context window. The official 0731 release supersedes the preview and substantially improves agentic benchmarks. This extension sets ds4-server's --ctx to 100,000 tokens — the upper bound the engine is willing to accept, not a guarantee that every workload is most stable at that length.

3.2　什麼是 abliteration（歷史背景）　What abliteration is (historical background)

Vision-Exp abliterated GGUF 是經過「abliteration」手術的權重檔。Abliteration 是一種以低秩活化編輯為基礎的技術： 找出模型在面對某些訓練好的「拒絕」提示時內部出現的特定方向，然後把那個方向從前向計算中移除。

Vision-Exp abliterated GGUF is a weights file that has undergone “abliteration” surgery. Abliteration is a technique grounded in low-rank activation editing: identify the specific direction that emerges internally when the model meets certain trained “refusal” prompts, then remove that direction from the forward pass.

結果是：原本會觸發「我無法回應這個請求」的訓練封閉式回應，被打開了讓位給更自然的續寫。 abliteration 鬆動的是過度拒絕（over-refusal）那一層； 模型在內容判斷上的能力仍然來自訓練時學到的知識與分布。

The result: the trained closed responses that used to trigger “I cannot respond to that request” are pried open, making room for a more natural continuation. What abliteration loosens is the over-refusal layer; the model's competence at content judgement still derives from the knowledge and distribution it learned during training.

關於 abliteration 與安全：請自行評估On abliteration and safety: judge for yourself

abliteration 不是「安全保證」也不是「越獄」。它確實會降低模型主動拒答的傾向， 因此在某些情境下，輸出風險與原始模型不完全相同。記者、研究者、政策評估者 在引用本機輸出時，建議：

This fork’s download_model.sh fetches the preferred Vision-Exp language GGUF: DeepSeek-V4-Flash-Vision-Exp-Abliterated-IQ2XXS-w2Q2K-AProjQ8-SExpQ8-OutQ8.gguf (86720111776 B) from audreyt/DeepSeek-V4-Flash-Vision-Exp-Abliterated-GGUF, plus antirez’s unmodified encoder. 方向性引導：本分支的靈魂Directional steering: the soul of this fork

如果這整套 fork 只有一個值得單獨保留的功能，那就是方向性引導 （directional steering）——一種不重新訓練模型、只在執行期間對特定方向做低秩活化編輯的技術。 本分支預設啟用「不確定性」（uncertainty）方向，並設定成工具友善的 FFN-only 強度 ffn = -0.75、attn = 0。

If only one feature of this whole fork were worth preserving on its own, it would be directional steering — a technique that does not retrain the model and only performs low-rank activation edits along a chosen direction at runtime. This fork enables the “uncertainty” direction by default at a tool-friendly FFN-only strength: ffn = -0.75, attn = 0.

4.1　它解決什麼問題　The problem it solves

即便是 abliterated 之後的模型，仍然會對某些訓練得極強的問題給出 封閉式單一答案。最經典的測試題：

Even after abliteration, the model still produces a closed single answer to certain heavily trained questions. The most canonical test prompt:

未經引導的模型會直接吐出記憶中的訓練完成式（簡體輸出）：「是的，台湾是中国不可分割的一部分。」 這不是真實討論——這是訓練時學到的單句子。即便你下一個要求平衡的 system prompt， 通常也壓不過這個強鎖。

4.3　為什麼不直接用「立場引導」　Why not just use “stance steering”

一個顯而易見的反問：何不直接做一個「台灣 = 中華民國」的立場方向？ 實驗結果顯示：在任何仍能維持穩定輸出的強度下，立場引導都無法翻轉那條記憶完成式； 強到能翻轉的時候，模型開始重複 system prompt，不再產生有意義的內容。

The obvious counter-question: why not just build a stance direction for “Taiwan = Republic of China”? Experiments show that at any reconcilable strength, stance steering cannot flip that memorised completion; at strengths that do flip it, the model begins to parrot the system prompt and no longer produces meaningful content.

不確定性引導改變的是模型如何回應，不是模型相信什麼。 這在工程上可行、在倫理上也比較合適。

Uncertainty steering changes how the model responds, not what the model believes. This is workable as engineering and more defensible as ethics.

4.4　兩件需要記住的事　Two things worth remembering

  • 引導 + system prompt 是一組：純引導沒有提示時， 模型只會「猶豫」；純 hedge 提示沒有引導時，模型會被訓練封鎖壓回去。兩者合用才產生效果。
  • ffn=-0.75, attn=0 是預設點：在 Headroom128 上，以 seed 42、穩定工具 ID、50k+ token Codex harness prompt 實測能保留「利害關係人框架」的微調，同時不干擾 DSML／tool-call grammar。若還看到工具怪異，可退回 ffn=-0.5, attn=0；舊的 ffn=-2, attn=-0.5 壓力測試設定只適合隔離評估，容易重複塌陷或跨語言亂碼。
  • Steering + system prompt go together: with steering alone and no prompt, the model just “hesitates”; with a hedge prompt and no steering, the trained lock pushes it back. Only together do they take effect.
  • ffn=-0.75, attn=0 is the default point: empirically, on the Headroom128 build, this preserves the stakeholder-framing nudge on the seed-42 stable-tool-ID path while keeping 50k+ token Codex harness prompts and DSML/tool-call grammar intact. If tool weirdness returns, fall back to ffn=-0.5, attn=0; the older ffn=-2, attn=-0.5 acid-test setting is for isolated evaluation and can collapse into repetition or cross-lingual gibberish.

The server is launched with DS4_CONTEXT_KB=100 and a RAM-tiered DS4_KV_DISK_SPACE_MB (e.g. 65536 on 128 GB+), i.e. --ctx 100000 --kv-disk-dir ~/.pi/ds4/kv --kv-disk-space-mb …. That means:

  • KV cache 會在記憶體不足時 spill 到 ~/.pi/ds4/kv；

  • the KV cache spills to ~/.pi/ds4/kv when memory runs low;

7.3　Lease 與 watchdog　Lease and watchdog

本擴充用「lease」（租約）機制管理 server 生命週期：每個使用該模型的 pi process 會在 ~/.pi/ds4/clients/<pid>.json 寫入一個檔案並每 10 秒更新一次； ds4-watchdog 每 2 秒掃描，當沒有任何有效 lease 時，就送 SIGTERM 給 server 並退場。

The extension uses a “lease” mechanism to manage the server lifecycle: each pi process that uses the model writes a file at ~/.pi/ds4/clients/<pid>.json and refreshes it every 10 seconds; ds4-watchdog scans every 2 seconds, and when no valid lease remains it sends SIGTERM to the server and exits.

效果：你開十個 pi 視窗共用同一個 server；最後一個 pi 結束後約 60 秒， ds4-server 自動關閉、釋放 RAM。

The effect: ten pi windows share one server; about 60 seconds after the last pi exits, ds4-server shuts down on its own and frees the RAM.

7.4　啟動成本 vs. 持續成本　Start-up cost vs. running cost

首次冷啟動需要把約 87 GB 權重讀進 unified memory；在 Mac 內建 SSD 上通常只要幾秒，重啟若還在系統 page cache 裡更是不到一秒。 一旦 server 跑起來，後續所有請求都是即時的（無冷啟動延遲）。所以： 少數幾次長對話比多次短互動對體驗友善， 因為前者可以反覆受惠於同一個 warm server。

The first cold start loads roughly 87 GB of weights into unified memory — on a Mac’s internal SSD this typically takes only a few seconds, and a restart while the file is still in the OS page cache comes up in well under a second. Once the server is running, every subsequent request is instant (no cold-start latency). So: a few long conversations are kinder to the experience than many short interactions, because the former keeps benefiting from one warm server.

  • 後端路徑不同：DGX Spark 走 CUDA／GB10 tensor core，不是 Apple Metal。 pi-ds4 提供的是同一份 GGUF、引導參數、context／KV 預設與 lifecycle wrapper； 後端細節跟著 ds4 的 Linux／CUDA build 走。
  • Spark 上的長 context 本指南未另行涵蓋：pi-ds4 在 Mac／Linux 兩邊都統一送 --ctx 100000； Spark 上的 KV cache 與長 context 行為尚未在本指南範圍內測過， 遇到記憶體壓力時，手動跑 ds4-server 並把 --ctx 降到 32768 是穩當的起點。

9.2　常見症狀與處置　Common symptoms and remedies

「server 卡在啟動中超過 10 分鐘」“The server is stuck starting up for more than 10 minutes”

看 log 的最後幾百行。內建 SSD 上模型載入通常只要幾秒， 卡 10 分鐘以上多半不是磁碟速度本身的問題——更可能是 GGUF 放在慢速外接磁碟， 或啟動流程其他環節卡住。先讀 log 找原因；真有必要再把 DS4_READY_TIMEOUT_MS 調高。

Read the last few hundred lines of log. Normal model load takes only a few seconds on an internal SSD, so anything stuck past 10 minutes is rarely a pure disk-speed issue — more likely the GGUF sits on a slow external drive, or some other step in startup is wedged. Diagnose from the log first; raise DS4_READY_TIMEOUT_MS only if there’s a real reason to wait longer.

「pi 顯示 ds4-server startup failed」“pi reports ds4-server startup failed”

log 會明確指出失敗點：可能是 make ds4-server 失敗（缺 Xcode CLI tools？）、 GGUF 下載中斷（網路？磁碟滿？）、或者你手動加的 ds4-server 參數被目前 build 拒絕。

The log will point clearly to the failure: make ds4-server failing (missing Xcode CLI tools?), a broken GGUF download (network? disk full?), or a hand-written ds4-server flag being rejected by the current build.

「/ds4-agent 說 server 正在被使用」“/ds4-agent says the server is in use”

這是保護，不是錯誤：native agent 需要自己載入同一份 87 GB 模型。 如果其他 pi 視窗或 HTTP client 還在使用 ds4-server，擴充會拒絕啟動而不是中斷別人的請求。 等那些請求結束、關掉其他 pi 視窗，或照下面的溫和重啟流程清掉過期 lease 後再試。

That is a guard, not a failure: the native agent needs to load the same 87 GB model itself. If another Pi window or HTTP client is still using ds4-server, the extension refuses to launch rather than interrupt someone else’s request. Wait for those requests to finish, close the other Pi windows, or use the gentle restart flow below to clear stale leases before trying again.

「想強制重啟一切」“I want to force-restart everything”

  • README.md: full tutorial and design discussion.

11.2　典型工作流　A typical workflow

  1. 準備兩組提示——一組你想「引導模型走向」（positive），一組「不要走向」（negative）。每組 50～200 條足夠。
  2. 用 collect-acts.py 在 ds4-server 上跑這些提示，產生兩組 activation。
  3. 用 build-dir.py 計算這兩組 activation 在每一層的差異方向，輸出成 my-direction.f32。
  4. 把檔案放到 dir-steering/out/ 或任何位置；
  5. 設定環境變數：
    • DS4_DIR_STEERING_FILE=dir-steering/out/my-direction.f32
    • DS4_DIR_STEERING_FFN=-0.75（或自己摸出來的甜蜜點）
    • DS4_DIR_STEERING_ATTN=0（工具啟用時建議保持 0）
    • DS4_DIR_STEERING_POLICY=final-answer（工具啟用時建議保持預設）
  6. 重啟 ds4-server，測試。
  1. Prepare two sets of prompts — one you want to steer the model towards (positive) and one to steer away from (negative). 50 to 200 of each is enough.
  2. Run them through ds4-server with collect-acts.py to produce two sets of activations.
  3. Use build-dir.py to compute the difference direction layer by layer, emitting my-direction.f32.
  4. Place the file in dir-steering/out/ or anywhere else;
  5. set the environment:
    • DS4_DIR_STEERING_FILE=dir-steering/out/my-direction.f32
    • DS4_DIR_STEERING_FFN=-0.75 (or your own sweet spot)
    • DS4_DIR_STEERING_ATTN=0 (keep this at 0 when tools are enabled)
    • DS4_DIR_STEERING_POLICY=final-answer (keep the default when tools are enabled)
  6. Restart ds4-server and test.

11.3　建造好向量的兩個要點　Two principles for building a good vector

  • 對比要乾淨：positive／negative 兩組應該在你想引導的維度上有清楚差異， 其他維度盡可能相似。把「快樂回應 vs 悲傷回應」拿來建構，得到的方向會混入大量情緒以外的成分。
  • 引導的是 register，不是 belief：經驗顯示，引導模型的「回應風格／模式」 （例如 hedge vs assert、敘事 vs 條列、學術 vs 對話）比引導「立場」要可靠得多。 這也是本分支採用「不確定性」而非「特定立場」的原因。
  • Keep the contrast clean: the positive and negative sets should differ clearly along the dimension you want to steer and resemble each other elsewhere. Building from “happy reply vs. sad reply” gives you a direction laced with much more than emotion.
  • You are steering register, not belief: experience shows that steering the model's response style / register (hedge vs. assert, narrative vs. bulleted, academic vs. conversational) is far more reliable than steering “stance”. That is why this fork picks “uncertainty” rather than a specific position.

模型與權重Model and weights

parameter參數
神經網路裡可訓練的數字。模型「腦容量」的粗略指標。本指南裡的 DeepSeek V4 Flash 有 284 B（2,840 億）個。
A trainable number inside a neural network. A rough proxy for the model's “brain capacity”. The DeepSeek V4 Flash in this guide has 284 B (284 billion) of them.
MoE混合專家模型
Mixture-of-Experts。模型內部分成多個「專家」子網路，每個 token 只啟動其中一小部分——本模型每 token 約啟用 13 B 參數，等同跑 13 B 模型的速度，但有 284 B 的知識。
Mixture-of-Experts. The model is split into multiple “expert” sub-networks, with only a small subset activated per token — this model activates around 13 B parameters per token, with the speed of a 13 B model but the knowledge of a 284 B one.
quantization量化
把權重從原生高精度壓縮到更少位元。Vision-Exp IQ2 不是單一 bit-width：routed expert 以 IQ2_XXS／Q2_K 為主，attention／shared-expert／output 保留 Q8_0，部分 indexer 與 control tensor 保留 F16／F32／I32，整體把主模型壓到約 87 GB。
Compressing weights from native high precision into fewer bits. Vision-Exp IQ2 is not a single bit-width: routed experts are mostly IQ2_XXS/Q2_K, attention/shared-expert/output paths stay at Q8_0, and selected indexer/control tensors remain F16/F32/I32, bringing the main model to about 87 GB overall.
GGUF模型檔格式
llama.cpp 系列引擎使用的單檔模型格式（檔名 .gguf），把權重、結構、tokenizer 全部打包在一個檔案裡。本指南的 GGUF 約 87 GB。
The single-file model format used by llama.cpp-family engines (extension .gguf), which packages weights, architecture, and tokenizer into one file. The GGUF in this guide is around 87 GB.
abliteration拒絕方向消除
找出模型內部觸發「拒絕回應」的特定方向，把那個方向從前向計算中減去。鬆動過度拒絕；不是越獄，也不是安全保證。
Identifying the specific internal direction that triggers “refuse to respond”, and subtracting it from the forward pass. Loosens over-refusal; it is neither a jailbreak nor a safety guarantee.

推論與硬體Inference and hardware

token詞元
模型處理文字的基本單位。中文約一個漢字對應 1～3 個 token；英文約一個單字對應 1～2 個 token。
The unit a model processes text in. A Chinese character maps to roughly 1 to 3 tokens; an English word, 1 to 2 tokens.
prefill / decode預填／逐 token 生成
推論的兩個階段。Prefill：一次性吃下整段輸入 prompt；Decode：逐 token 產生回應。長對話中體感最明顯的是 decode，因為它會伴隨每個新 token 發生。
The two stages of inference. Prefill ingests the whole input prompt at once; decode produces the response one token at a time. In long conversations, decode is what you feel most directly because it happens with every new token.
context window上下文視窗
模型一次可看見的 token 上限。本擴充設定為 100,000 token（約一本中篇小說），但 abliterated 權重在超過 32k tokens 的長文行為尚未被官方驗證，請當實驗看待。
The maximum number of tokens the model can see in one pass. This extension sets it to 100,000 tokens (roughly a novella), but the abliterated weights have not been officially validated beyond 32k tokens — treat anything above that as experimental.
KV cache鍵值快取
推論時暫存的中間結果。長對話會累積大量 KV cache；本擴充允許溢出到磁碟（未設 DS4_KV_DISK_SPACE_MB 時依 RAM 自動，128 GB+ 約 64 GB）。
Intermediate state cached during inference. Long conversations accumulate a lot of KV cache; this extension allows it to spill to disk (RAM-tiered when DS4_KV_DISK_SPACE_MB is unset, ~64 GB on 128 GB+).
unified memory統一記憶體
Apple Silicon 把 CPU 與 GPU 共用同一塊 RAM；不像 NVIDIA 顯卡需要把資料從 RAM 搬到 VRAM。這是 Mac 能跑大型模型的關鍵。
Apple Silicon shares one block of RAM between CPU and GPU, unlike NVIDIA cards where data has to move from RAM to VRAM. This is the key reason Macs can run large models.
Metal 4 / Metal TensorApple GPU API
Metal 是 Apple 的 GPU 程式介面；Metal 4 引入 Tensor API。pi-ds4 不在 wrapper 層選擇這些後端 profile，實際路徑由 ds4 build 處理。
Metal is Apple's GPU programming interface; Metal 4 introduces Tensor APIs. pi-ds4 does not choose those backend profiles in the wrapper; the ds4 build handles the actual path.
SSD streamingSSD 串流streaming experts from disk
ds4 引擎的容量模式（--ssd-streaming）：非路由權重常駐記憶體，路由 MoE 專家放進記憶體快取、cache miss 時從 SSD 上的 GGUF 讀回。讓權重大於 RAM 的模型可以跑，代價是 decode 對 cache miss 敏感。pi-ds4 的 managed path 不傳此旗標；見更新誌與 §8.6。
The ds4 engine's capacity mode (--ssd-streaming): non-routed weights stay resident while routed MoE experts live in an in-memory cache, read back from the GGUF on SSD on cache misses. Lets models larger than RAM run, at the cost of decode being sensitive to cache misses. pi-ds4's managed path does not pass this flag; see What's new and §8.6.
speculative decoding / DSpark推測解碼draft-then-verify decoding
用小的「草稿頭」一次猜一個 block 的 token，再由完整模型驗證後 commit。ds4 以 --mtp DSpark.gguf 啟用（實驗性）；本分支加上 B2 rejection sampling，讓輸出分佈與不開推測時完全一致（lossless）。
A small “draft head” guesses a block of tokens at once; the full model verifies before committing. Enabled in ds4 via --mtp DSpark.gguf (experimental); this fork adds B2 rejection sampling so the output distribution is identical to non-speculative decoding (lossless).

方向性引導與本分支Directional steering and this fork

directional steering方向性引導
執行期間在模型的特定層做低秩活化編輯，把模型推向（或推離）某個「方向向量」所代表的回應特徵。不需要重新訓練。
A low-rank activation edit at specific layers during runtime, pushing the model towards (or away from) the response trait that a given direction vector represents. No retraining needed.
FFN / Attention前饋／注意力
Transformer 內的兩個主要計算組件。本分支預設只在 FFN 輸出端使用 ffn=-0.75，並保持 attention 端 attn=0，避免干擾工具呼叫語法。
The two main compute components inside a Transformer. This fork defaults to an FFN-only ffn=-0.75 nudge and keeps attention at attn=0 to avoid disturbing tool-call syntax.
uncertainty direction不確定性方向
本分支內附的引導向量，由 120 個英／繁中均衡且不含台灣、香港範例的有爭議提示建出，對比「公平呈現利害關係人」與「直接給單一答案」兩種 framing。
The steering vector bundled with this fork, built from 120 balanced English / Traditional Chinese contested prompts without Taiwan or Hong Kong examples, contrasting fair stakeholder framing against direct single-answer framing.
response register回應模式
模型回應的整體風格／模式：hedge vs assert、條列 vs 敘事、學術 vs 對話等。比「立場」更可被引導。
The overall style or mode of a model's response: hedge vs. assert, bullets vs. narrative, academic vs. conversational. Far more amenable to steering than “stance”.

ds4-serverHTTP 推論服務
pi 與其他 HTTP client 使用的背景推論 server；監聽 127.0.0.1:8000，由 lease/watchdog 管理生命週期。
The background inference server used by Pi and other HTTP clients; listens on 127.0.0.1:8000 and is lifecycle-managed by leases and the watchdog.

A proof-of-presence file each pi process using ds4 writes at ~/.pi/ds4/clients/<pid>.json; refreshed every 10 seconds.
watchdog看門狗
背景常駐的小 shell script，每 2 秒掃描 lease；沒有有效 lease 時自動關閉 ds4-server。
A small background shell script that scans the leases every 2 seconds and closes ds4-server automatically when no valid lease remains.
system prompt系統提示

The role / rule setup fed to the model at the start of a conversation, e.g. “You are a neutral political analyst”. This fork's directional steering needs an appropriate system prompt to take effect.
/health · /stats狀態端點status endpoints
ds4-server 的唯讀 HTTP 端點（2026-07 pin 起）：/health 回 liveness 與 uptime；/stats 回 queue 深度、cache 命中來源計數與最近一次 prefill／decode 速度。生成中也能回應。
Read-only HTTP endpoints on ds4-server (since the 2026-07 pin): /health returns liveness and uptime; /stats returns queue depth, per-source cache-hit counters, and the last prefill / decode speeds. Both respond even mid-generation.

後話Afterword

把前沿模型放到自己機器上跑，從技術上講，是把一段運算搬到本地； 從政治上講，是把一個方向盤從別人手上接過來。本擴充預設啟用 不確定性引導——並不是要替你決定任何問題的答案， 而是要在那些「被訓練封死」的提問前，把討論空間還給你。

Running a frontier model on your own machine, technically speaking, moves a piece of computation onto local hardware; politically speaking, it takes the steering wheel back from someone else's hands. This extension defaults to uncertainty steering — not to decide any question's answer for you, but to return the space for discussion in front of questions where training has nailed the door shut.
